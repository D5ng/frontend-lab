# 변경 요청: 자리가 다 찬 수업의 대기 신청

- 역할: 확인 · 20~30분
- 유형: 변경 요청. 문제 2에서 바꾼 코드 위에 구현합니다.
- 도메인: 예약 (필라테스 수업, 문제 2 이어서)
- SEED: 문제 2와 같습니다

```bash
pnpm --filter @frontend-lab/drills test problems/2026-11-02-abstraction-level
```

## 요청

> 스튜디오 운영: "인기 수업은 금방 차서 회원님들이 자리가 났는지 계속 들어와 보세요. 자리가 다 찬 수업도 대기 신청을 받을게요. 대기는 수강권을 바로 쓰지 않고, 자리가 나면 대기 순서대로 예약해 드려요. 수업 4시간 전까지 자리가 안 나면 대기는 저절로 취소돼요."

자리가 다 찬 수업에서만 바뀝니다. 자리가 남은 수업은 지금처럼 예약합니다.

| 자리           | 자리가 다 찼을 때 (새로)                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 남은 자리      | `자리가 모두 찼어요` 아래에 `지금 3명이 기다리고 있어요`                                                                                |
| 안내           | 취소 규칙 대신 `11월 4일 (수) 오후 3:00까지 자리가 나지 않으면 대기는 저절로 취소돼요. 자리가 나면 대기 순서대로 예약하고 알려 드려요.` |
| 하단 버튼      | `대기 신청하기`. 신청하는 동안은 예약하기와 똑같이 잠근다                                                                               |
| 신청한 뒤      | 버튼 자리에 `대기 4번째예요`(잠김), `Snackbar`로 `대기 신청했어요. 자리가 나면 알려 드릴게요.`. 수강권은 그대로이고 바꿀 수 없다        |
| 신청 실패      | `Snackbar`로 `대기 신청하지 못했어요. 잠시 후 다시 시도해 주세요.`                                                                      |
| 다시 열었을 때 | 이미 대기 중이면 처음부터 `대기 N번째예요`와 대기에 건 수강권을 보여 준다                                                               |

- 대기 기한은 취소 기한과 같은 시각입니다(수업 시작 4시간 전).
- 쓸 수 있는 수강권이 없으면 대기 신청도 할 수 없습니다.

## 바뀐 API

수업 응답의 `waitlistCount`는 서버가 원래 보내고 있었고, 지금까지 아무도 안 썼습니다. 내 대기 정보가 새로 생깁니다.

```json
{
  "gymClass": {
    "...": "문제 2와 같음",
    "bookedCount": 8,
    "waitlistCount": 3,
    "myWaitlist": null
  }
}
```

대기 중이면 `"myWaitlist": { "passId": "group-30", "position": 2 }`입니다.

```http
POST /api/drills/2026-11-02/classes/mat-1104-1900/waitlist
{ "passId": "group-10" }
```

대기 신청한 뒤의 수업과 수강권을 문제 2와 같은 모양으로 돌려줍니다(`201`). 이 주소의 모의 서버는 `problem-3/handlers.ts`에 있습니다. `api.ts`에 요청 함수와 새 필드를 더하는 것은 풀이에 들어갑니다.

테스트는 응답을 스스로 덮어써서 자리가 다 찬 수업을 만듭니다. 화면에서 보고 싶으면 `problem-2/handlers.ts`의 `bookedCount`를 `8`로, `waitlistCount`를 `3`으로 바꿉니다. 다 보고 나면 되돌립니다. 문제 2의 테스트는 자리가 남은 수업을 기준으로 씁니다.
