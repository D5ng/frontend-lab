# 한 컴포넌트 안에서 추상화 높이 맞추기

읽기 5분. 오늘 세 문제는 모두 이 기법 하나만 씁니다.

## 개념

컴포넌트 하나를 위에서부터 읽을 때 **줄마다 같은 높이에서 말하게** 하는 것입니다.

높이는 "무엇을 하는가"와 "어떻게 하는가" 사이의 거리입니다. `<ClassSummary />`는 "수업 요약을 보여 준다"는 높은 줄이고, `new Date(startsAt).getTime() - hours * 60 * 60 * 1000`은 "시작 시각에서 몇 시간을 밀리초로 뺀다"는 낮은 줄입니다. 둘 다 맞는 코드지만, 한 컴포넌트 안에 나란히 있으면 읽는 사람은 높이를 계속 오르내려야 합니다.

책의 목차를 떠올리면 쉽습니다. 목차 사이에 본문 한 쪽이 끼어 있으면, 목차를 훑으려던 사람은 그 쪽을 다 읽거나 건너뛸 곳을 찾아야 합니다.

사람의 말로 바꾸면 이 질문입니다.

> "이 컴포넌트를 소리 내어 읽으면, 문장마다 같은 크기로 들리나?"

> "이 화면을 한 문장씩 설명하다가 갑자기 '그리고 여기서 밀리초를 빼서…'가 끼어들지 않나?"

## 낮을 때 보이는 신호

- 한 줄짜리 컴포넌트 이름 바로 옆에 계산식, 두 단짜리 삼항, 태그 스무 줄이 나란히 있다.
- 화면의 어떤 구역은 컴포넌트로 빠져 있고, 어떤 구역은 펼쳐져 있다. 빠진 기준이 "무엇인가"가 아니라 "누가 먼저 뺐는가"다.
- 같은 화면을 설명하는데 어떤 구역은 "남은 자리를 보여 준다"로 끝나고, 어떤 구역은 "정원에서 예약 인원을 빼서 0 이하면 이 문구, 2 이하면 배지…"까지 읽어야 끝난다.
- 기능 하나를 더할 때 화면 컴포넌트 한가운데에 계산과 태그가 한 덩어리로 들어간다. 다음 기능도 같은 자리에 들어간다.

## 흔한 오해 두 가지

1. **"높이를 맞추려면 전부 작은 컴포넌트로 쪼갠다."** 세 줄짜리 컴포넌트를 열 개 만들면 맨 위는 깔끔해 보여도, 하나를 이해하려고 파일 다섯 개를 오가게 됩니다. 높이를 맞추는 일은 **이름을 붙이는 일**이지 쪼개는 일이 아닙니다. 같은 파일 안 함수 하나, 잘 지은 변수 하나로도 맞출 수 있습니다. 이미 한 높이로 읽히는 짧은 태그는 그대로 둬도 됩니다.
2. **"꺼내기만 하면 높이가 올라간다."** `<YellowBox>`, `<Section2>`, `<CardTop>`처럼 **모양이나 위치로 지은 이름**은 아래 내용을 감추지 못합니다. 읽는 사람은 무엇이 들어 있는지 알려고 결국 열어 봅니다. 이름이 "무엇"을 말해야 높이가 올라갑니다.

더 읽을거리: 로버트 C. 마틴, 『Clean Code』 3장 "함수 당 추상화 수준은 하나로"

| ---------------------------- | --------------------------------------------- |
| 추상화 높이(수준)            | `level of abstraction`                        |

| 강사                         | `instructor`                                  |
| 정원 / 예약 인원 / 남은 자리 | `capacity` / `bookedCount` / `remainingSeats` |
| 마감 임박 / 자리가 다 참     | `almostFull` / `full`, `soldOut`              |
| 수강권 / 남은 횟수           | `pass` / `remainingCount`                     |
| 기간이 끝남                  | `expired`, `expiresAt`                        |
| 쓸 수 있는                   | `usable`, `available`                         |
| 취소 기한                    | `cancelDeadline`                              |
| 대기 / 대기 순서             | `waitlist` / `position`                       |
| 예약 안내 / 요약             | `notice` / `summary`                          |
