# 원룸 매물 목록과 상세

- 역할: 적용 · 30분
- 유형: 리팩터링. 동작하는 시작 코드와 이미 통과하는 행동 테스트가 있습니다.
- 도메인: 부동산 (원룸 월세)
- SEED: `List` + `ListButtonItem` · `ListItem` · `ListHeader`, `Chip.RadioRoot`, `Badge`, `ContentPlaceholder`, `Skeleton`, `Callout`, `ActionButton`, `Snackbar`

```bash
pnpm dev
pnpm --filter @frontend-lab/drills test problems/2026-10-31-separate-response-shape
```

## 화면

> 자취방을 구하는 사람이 이 동네 월세 원룸을 훑어보고, 마음에 드는 방을 골라 방 보기를 요청한다.

```text
원룸 찾기 (목록) ──▶ 방 정보 (상세) ──▶ 방 보기 요청
```

- 목록에서는 방을 고를 때 먼저 보는 것만 한 줄씩 보여 줍니다. 옵션과 설명은 상세에서 봅니다.
- 정렬은 둘 중 하나를 고르는 일이라 목록 위에 칩으로 둡니다. 고르는 즉시 목록이 바뀝니다.
- 방 보기 요청은 되돌릴 일이 없고 화면에 남길 내용도 없어서 결과를 `Snackbar`로 알리고, 버튼 문구를 바꿔 다시 누르지 않게 합니다.

| 상태     | 보여 주는 것                                                                      |
| -------- | --------------------------------------------------------------------------------- |
| 불러오기 | 목록과 상세 모두 들어올 자리에 `Skeleton`                                         |
| 실패     | 불러오기 실패는 `Callout`과 다시 불러오기, 방 보기 요청 실패는 `Snackbar`         |
| 빈 상태  | 올라온 방이 없다는 안내. 걸러 낼 조건이 없어서 버튼은 두지 않습니다               |
| 비활성   | 요청 중에는 버튼에 불러오는 표시, 요청한 뒤에는 "방 보기를 요청했어요"로 잠깁니다 |
| 성공     | `Snackbar`로 요청했다고 알립니다                                                  |

## 모의 API

모의 서버(`handlers.ts`)는 풀이 대상이 아닙니다. 응답 모양은 서버 팀이 정했고, 이 화면 때문에 바꿀 수 없습니다.

```http
GET /api/drills/2026-10-31/rooms
```

```json
{
  "rooms": [
    {
      "room_id": 301,
      "title": "역까지 걸어서 5분, 햇빛 잘 드는 원룸",
      "deposit": 500,
      "monthly_rent": 45,
      "maintenance_fee": 7,
      "area_m2": 23.1,
      "floor": "3/5",
      "available_from": null
    }
  ],
  "total_count": 5
}
```

- 돈은 모두 **만원** 단위입니다.
- `floor`는 `"지금 층/건물 전체 층수"`입니다.
- `available_from`이 `null`이면 바로 들어갈 수 있고, 날짜(`"2026-11-15"`)면 그날부터 들어갈 수 있습니다.

```http
GET /api/drills/2026-10-31/rooms/301
```

목록 응답의 필드에 `description`(설명)과 `options`(`["AIRCON", "WASHER", "FRIDGE", "BED"]`)가 더해집니다.

```http
POST /api/drills/2026-10-31/rooms/301/visit-requests
```

`201`이면 요청한 것입니다. 실패(`500`)는 화면에서 재현되지 않고 테스트에서 확인합니다.

## 응답을 읽는 곳

| 화면       | 파일               | 응답에서 읽는 것                                                                 |
| ---------- | ------------------ | -------------------------------------------------------------------------------- |
| 목록 정렬  | `RoomList.tsx`     | 매달 드는 돈 적은 순으로 줄 세우기                                               |
| 목록 한 줄 | `RoomListItem.tsx` | 보증금/월세, 관리비, 평수, 층, 바로 입주 표시                                    |
| 방 정보    | `RoomDetail.tsx`   | 보증금, 월세, 관리비, 매달 드는 돈, 크기와 평수, 층과 전체 층수, 입주 날짜, 옵션 |

세 곳은 지금 같은 기준으로 보여 주고, 테스트도 모두 통과합니다.

## 할 일

1. 화면 동작은 그대로 두고, 컴포넌트가 서버 응답 모양을 직접 알지 않아도 되게 바꿉니다. `Problem.spec.tsx`는 그대로 통과해야 합니다.
2. 바꾼 곳에 화면 없이 도는 테스트를 하나 붙입니다. 방 하나(`room_id: 301`)면 충분합니다.
3. `note.md`의 질문에 답합니다.
