# 버그: 관리비가 null만원으로 보여요

- 역할: 확인 · 20~30분
- 유형: 버그 추적. 문제 2에서 바꾼 코드 위에서 재현하고, 다시 생기지 않게 고칩니다.
- 도메인: 부동산 (원룸 월세, 문제 2 이어서)
- SEED: 문제 2와 같습니다

## 들어온 문의

> 고객센터: "오늘 올라온 방 하나가 목록에서 '관리비 null만'으로 보여요. 매달 드는 돈 적은 순으로 보면 그 방이 맨 위에 있는데, 눌러 보면 관리비도 'null만원'이고 매달 드는 돈은 월세만큼만 나와요. 사용자가 관리비 없는 방인 줄 알고 문의했어요."

서버 팀에 물어보니 이렇게 답했습니다.

> "집주인이 관리비를 아직 정하지 않은 방은 `maintenance_fee`를 `null`로 보내요. 원래부터 그렇게 약속된 값인데 지금까지는 그런 방이 없었어요. 0은 관리비가 없는 방이에요."

기획에서 정한 표시는 이렇습니다.

| 어디                   | 관리비를 아는 방   | 관리비를 아직 정하지 않은 방 |
| ---------------------- | ------------------ | ---------------------------- |
| 목록 한 줄             | `관리비 7만`       | `관리비 문의`                |
| 매달 드는 돈 정렬      | 월세 + 관리비 순서 | 관리비를 아는 방들 **뒤에**  |
| 방 정보의 관리비       | `7만원`            | `집주인에게 문의`            |
| 방 정보의 매달 드는 돈 | `52만원`           | `35만원 + 관리비`            |

## 재현

`Problem.spec.tsx`가 관리비를 정하지 않은 방(`room_id: 306`)을 응답에 넣어 둡니다. `it.skip`을 `it`으로 바꾸고 테스트를 돌리면 세 테스트가 실패합니다. 그게 재현입니다.

화면에서 직접 보고 싶으면 `problem-2/handlers.ts`의 `rooms` 끝에 아래 방을 잠깐 넣습니다. 확인한 뒤에는 지웁니다. 문제 2 테스트는 방이 다섯 개라고 가정합니다.

```ts
{
  room_id: 306,
  title: '방금 올라온 넓은 원룸',
  deposit: 300,
  monthly_rent: 35,
  maintenance_fee: null,
  area_m2: 33.0,
  floor: '2/3',
  available_from: null,
  description: '관리비는 집주인이 정하는 중이에요.',
  options: ['AIRCON'],
},
```
