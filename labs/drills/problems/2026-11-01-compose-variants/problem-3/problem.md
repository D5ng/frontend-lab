## 요청 두 가지

> 모임 기획: "모임 일정이 바뀌면 알림함에도 남겨 주세요. 언제에서 언제로 바뀌었는지 한눈에 보이게, 바뀌기 전 일정은 줄을 긋고 바뀐 일정을 그 아래에 써 주세요. 답할 것이 없는 알림이라 버튼은 없어요."

> 커뮤니티 기획: "댓글 알림에서 바로 그 댓글에 좋아요를 누를 수 있게 해 주세요. 댓글 내용 아래에 작은 좋아요 버튼 하나면 돼요. 좋아요 알림이나 초대 알림에는 필요 없어요."

| 종류             | 앞쪽        | 첫 줄                                    | 그 아래                                    | 맨 아래       |
| ---------------- | ----------- | ---------------------------------------- | ------------------------------------------ | ------------- |
| 일정 변경 (새로) | 달력 아이콘 | `망원 책 읽는 밤 모임 일정이 바뀌었어요` | 바뀌기 전 일정(줄 긋기), 그 아래 바뀐 일정 | 없음          |
| 댓글 (바뀜)      | 그대로      | 그대로                                   | 댓글 내용                                  | `좋아요` 버튼 |

- 일정은 `schedule.ts`의 `formatSchedule`로 `11월 6일 (금) 오후 7:30`처럼 씁니다. 줄 긋기는 `<del>`로 합니다.
- 일정 변경 알림도 다른 알림과 똑같이 받은 시각과 `읽지 않음`을 보여 줍니다.
- 좋아요 버튼은 `ReactionButton`입니다. `pressed`와 `onPressedChange`로 눌림을 다룹니다. 누르면 눌린 채로 바뀌고, 다시 누르면 취소합니다. 요청이 실패하면 누르기 전으로 되돌립니다.

## 바뀐 API

알림 목록 응답에 새 종류가 생깁니다.

```json
{
  "id": 6,
  "type": "scheduleChanged",
  "createdAt": "2026-10-27T21:00:00+09:00",
  "read": true,
  "group": { "name": "망원 책 읽는 밤" },
  "before": "2026-11-06T19:30:00+09:00",
  "after": "2026-11-07T19:30:00+09:00"
}
```

댓글 알림의 `comment.id`와 `comment.likedByMe`는 서버가 원래 보내고 있었고, 지금까지 아무도 안 썼습니다.

```http
POST /api/drills/2026-11-01/comments/501/likes
DELETE /api/drills/2026-11-01/comments/501/likes
```

`POST`가 좋아요(`201`), `DELETE`가 취소(`204`)입니다. 이 두 주소의 모의 서버는 `problem-3/handlers.ts`에 있습니다. `api.ts`에 요청 함수와 새 알림 타입을 더하는 것은 풀이에 들어갑니다.

테스트는 응답을 스스로 덮어써서 일정 변경 알림을 넣습니다. 화면에서 보고 싶으면 위 JSON을 `problem-2/handlers.ts`의 `notifications` **맨 끝**에 넣습니다. 맨 끝에 두면 문제 2의 테스트도 그대로 통과하므로 남겨 둬도 됩니다.
