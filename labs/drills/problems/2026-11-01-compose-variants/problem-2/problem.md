# 동네 모임 알림함

- 역할: 적용 · 30분
- 유형: 직접 구현. 요구사항, API, 다 그려 둔 화면이 있고 동작은 없습니다. 행동 테스트는 `it.skip`으로 들어 있습니다.
- 도메인: 커뮤니티 (동네 모임 앱의 알림)
- SEED: `Avatar` · `AvatarStack`(`seed-design/ui/avatar`), `ImageFrame`, `ActionButton`, `Skeleton`, `Callout`, `VisuallyHidden`

```bash
pnpm dev
pnpm --filter @frontend-lab/drills test problems/2026-11-01-compose-variants/problem-2
```

## 화면

> 동네 모임 앱을 쓰는 사람이 놓친 소식을 한 화면에서 훑어보고, 모임 초대에는 그 자리에서 답한다.

```text
알림 (목록 한 화면)
```

- 알림을 눌러 글이나 모임으로 가는 이동은 이번 범위가 아닙니다. 읽음 처리도 하지 않습니다. 이 화면의 일은 훑어보기와 초대에 답하기입니다.
- 초대에는 화면을 옮기지 않고 그 알림 안에서 답합니다. 고를 것이 둘뿐이고, 모임 사진과 초대한 사람이 이미 알림에 다 보이기 때문입니다.
- 답한 결과는 나중에 다시 봐도 보여야 해서, 잠깐 뜨고 사라지는 안내 대신 버튼이 있던 자리에 남깁니다.

## 알림 세 종류

| 종류      | 앞쪽                               | 첫 줄                                                                                 | 그 아래                        | 맨 아래                                                                               |
| --------- | ---------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------- |
| 댓글      | 댓글 단 사람 사진                  | `김민지님이 내 글에 댓글을 남겼어요`                                                  | 댓글 내용. 두 줄이 넘으면 줄임 | 없음                                                                                  |
| 좋아요    | 누른 사람 사진을 겹쳐서, 세 명까지 | 여러 명: `김민지님 외 3명이 내 글을 좋아해요`<br>한 명: `이서연님이 내 글을 좋아해요` | 글 제목                        | 없음                                                                                  |
| 모임 초대 | 모임 사진                          | `박준호님이 주말 러닝 크루에 초대했어요`                                              | `멤버 24명`                    | 답하기 전: `거절` `참여하기`<br>답한 뒤: `모임에 참여했어요` 또는 `초대를 거절했어요` |

종류와 상관없이 모든 알림이 똑같이 하는 것

- 응답에 온 순서 그대로 세로 목록으로 보여 줍니다. 목록은 `ul`과 `li`로 만듭니다. 스크린리더가 알림이 몇 개인지 읽어 줍니다.
- 그 아래 내용 다음 줄에 언제 받았는지 보여 줍니다. `time.ts`의 `formatTimeAgo(createdAt, now)`를 씁니다. `now`는 응답에 있습니다.
- 첫 줄의 사람 이름과 모임 이름은 굵게 씁니다. 테스트는 굵게 썼는지와 상관없이 문장으로 찾습니다.
- 읽지 않은 알림(`read: false`)은 배경을 `bg.brandWeak`로 칠하고, 스크린리더에는 `읽지 않음`을 읽어 줍니다(`VisuallyHidden`).

| 상태     | 보여 주는 것                                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 불러오기 | 알림이 들어올 자리에 `Skeleton`                                                                                  |
| 실패     | 불러오기 실패는 `Callout`과 `다시 불러오기`. 초대에 답하지 못하면 버튼 아래 `답하지 못했어요. 다시 눌러 주세요.` |
| 빈 상태  | `아직 받은 알림이 없어요`. 알림은 사용자가 만드는 것이 아니라서 버튼은 두지 않습니다                             |
| 비활성   | 초대에 답하는 동안 그 알림의 두 버튼을 모두 잠그고, 누른 버튼에 불러오는 표시                                    |
| 성공     | 버튼 자리가 결과 문구로 바뀝니다                                                                                 |

`ActionButton`의 `loading`은 모양만 바꾸고 누르기를 막지 않습니다. 잠그려면 `disabled`도 함께 줍니다.

## 모의 API

모의 서버(`handlers.ts`)는 풀이 대상이 아닙니다. 응답 타입과 요청 함수는 `api.ts`에 있습니다.

```http
GET /api/drills/2026-11-01/notifications
```

```json
{
  "now": "2026-11-01T09:00:00+09:00",
  "notifications": [
    {
      "id": 1,
      "type": "comment",
      "createdAt": "2026-11-01T08:57:00+09:00",
      "read": false,
      "actor": { "name": "김민지", "profileImageUrl": "..." },
      "comment": { "id": 501, "text": "다음엔 저도 같이 뛰어요! ...", "likedByMe": false }
    },
    {
      "id": 2,
      "type": "like",
      "createdAt": "2026-11-01T07:00:00+09:00",
      "read": false,
      "actors": [{ "name": "김민지", "profileImageUrl": "..." }, "... 모두 4명"],
      "postTitle": "토요일 아침 한강 러닝 후기"
    },
    {
      "id": 3,
      "type": "invite",
      "createdAt": "2026-10-31T08:10:00+09:00",
      "read": true,
      "inviter": { "name": "박준호", "profileImageUrl": "..." },
      "group": { "name": "주말 러닝 크루", "imageUrl": "...", "memberCount": 24 },
      "status": "pending"
    }
  ]
}
```

`status`는 `pending`(아직 답하지 않음), `accepted`(참여함), `declined`(거절함) 중 하나입니다. 실제 응답에는 알림이 다섯 개 있고, 그중 하나는 이미 참여한 초대입니다.

```http
POST /api/drills/2026-11-01/notifications/3/answer
{ "accept": true }
```

`{ "status": "accepted" }`처럼 답한 결과를 돌려줍니다. 실패(`500`)는 화면에서 재현되지 않고 테스트에서 확인합니다.

## 주는 것

| 파일               | 내용                                    |
| ------------------ | --------------------------------------- |
| `Problem.tsx`      | 다 그려 둔 정적 화면. 동작은 없음       |
| `api.ts`           | 응답 타입, `fetchInbox`, `answerInvite` |
| `time.ts`          | `formatTimeAgo`                         |
| `handlers.ts`      | 모의 서버                               |
| `Problem.spec.tsx` | 행동 테스트. 모두 `it.skip`             |

`Problem.tsx`에 그려 둔 것

- 알림 다섯 개를 응답 순서대로 `ul`/`li`에 그대로 적어 두었습니다. 값은 `handlers.ts`의 응답과 같습니다. `map`으로 바꾸는 것, 컴포넌트와 파일을 나누는 것은 풀이입니다.
- 처음에는 안 보이는 모양은 주석으로 넣고, 바로 위에 언제 보여 줄지 적었습니다: 불러오는 중(`Skeleton`), 불러오기 실패(`Callout`과 `다시 불러오기`), 빈 상태, 초대에 답하는 중(두 버튼 잠금과 `loading`), 답하지 못함, 거절한 뒤. 참여한 뒤의 모양은 맨 아래 초대 알림에 있습니다.
- 사람 사진은 비워 두어 이름 첫 글자가 보입니다. 응답의 `profileImageUrl`을 넣으면 사진이 나옵니다.

SEED 쓰는 법 메모

- `Avatar`는 `size="42"`, `src`, `fallback`(이름 첫 글자)을 받습니다. 겹쳐 보이려면 `AvatarStack size="24"`으로 `Avatar` 여럿을 감쌉니다.
- `ImageFrame`은 `src`, `alt`, `ratio={1}`을 받고 폭을 채웁니다. 크기는 감싼 `Box`의 `width`로 정합니다.
- `Text`의 `maxLines={2}`로 두 줄 넘는 글을 줄입니다.

2. `pnpm dev`로 띄워 375px 너비에서 초대에 답해 봅니다.
3. `note.md`의 질문에 답합니다.
