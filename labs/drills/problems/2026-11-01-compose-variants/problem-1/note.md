# 풀이 기록 · 상품 카드의 boolean props 정리하기

답은 질문마다 2~3줄이면 충분합니다.

## 바꾸기 전 props 여덟 개 중 "어떤 조각을 보여 줄지 고르는 것"과 "카드가 늘 지켜야 하는 것"은 각각 무엇이었나요? 바꾼 뒤 각각 어디로 갔나요?

#### 어떤 조각을 보여줄지 고르는 것:

`product`, `thumbnail`, `action`을 보여주도록 구성하고, 나머지 `prop`은 제거했어요.

상품 이미지, 순위, 품절은 UI가 함께 있어요. 상품 이미지는 많이 산 상품과 검색 결과에서 노출되고, 함께 사면 좋은 상품에는 노출되지 않아요. 따라서 상품 이미지를 렌더링하는건 `slot`으로 받을 이유가 충분하다고 판단했고,
`ProductThumbnail` 컴포넌트를 재사용할 수 있도록 만들고. 순위와 품절은 `children`으로 받도록 해놓았어요.

`ProductThumbnail`에 `prop`으로도 받을 수 있지만, 초기 문제의 `ProductCard` 컴포넌트와 동일한 문제가 발생해요. 만약 다른 곳에서도 사용할 이유가 커진다면, 그때는 `prop`제공을 고민해볼 수 있을것 같아요.

#### (리뷰)

판단은 좋다. 특히 "`ProductThumbnail`에 `showRank`를 또 받으면 처음 문제가 그대로 옮겨 간다"는 지금 구조를 고른 이유를 정확히 말한다.

다만 질문은 **바꾸기 전 props 여덟 개**를 나누라는 것이었다. 답은 바꾼 뒤의 세 개(`product`, `thumbnail`, `action`)에서 출발해서, 원래 props가 각각 어디로 갔는지가 안 보인다. 여덟 개를 하나씩 대 보면 이렇다.

| 바꾸기 전                       | 고르는 것 / 지키는 것     | 바꾼 뒤                                                 |
| ------------------------------- | ------------------------- | ------------------------------------------------------- |
| `product`                       | 데이터                    | 그대로                                                  |
| `compact`(사진 숨김)            | 고르는 것                 | `thumbnail`을 안 넘기면 사진이 없다                     |
| `showRank`, `rank`              | 고르는 것                 | 홈이 `ProductThumbnail`의 `children`으로 `1위`를 넣는다 |
| `showSoldOut`                   | 고르는 것                 | 쓰는 쪽이 `children`으로 품절 띠를 넣는다               |
| `compact`(짧은 버튼 글자)       | 고르는 것                 | `action.label`                                          |
| `showCartButton`, `onAddToCart` | 고르는 것                 | `action`이 있으면 버튼이 있다                           |
| `showDiscount`                  | 지키는 것 (세 곳 모두 켬) | 없앰. 카드가 늘 할인 줄을 그린다                        |

`compact` 하나가 사진과 버튼 글자 두 가지를 동시에 고르고 있었다는 점이 이 표에서 보인다. boolean 하나에 뜻이 둘 묶여 있으면, 사진은 없는데 긴 글자를 쓰는 화면이 생기는 순간 막힌다.

참고 답:

> 고르는 것: `showRank`·`rank`, `showSoldOut`, `compact`, `showCartButton`·`onAddToCart`. 사진 자리는 `thumbnail` 슬롯으로 열고 순위와 품절 띠는 `ProductThumbnail`의 `children`으로 쓰는 쪽이 넣는다. 버튼 자리는 `action`(글자와 할 일)으로 받는다. `compact`는 사진 숨김과 짧은 글자 두 뜻이 묶여 있어서 둘로 갈라졌다.

#### 늘 지켜야하는 것:

"할인율이 있으면 할인율, 할인한 가격, 원래 가격을 함께 보여주고, 할인한 가격은 10원 아래를 버려요."라는 정책이 있어요. 따라서 `ProductCard.tsx`에서 `showDiscount`를 제거했어요. 왜냐하면 어디서든 지켜야하는 규칙이기 때문이에요

"다 팔린 상품은 담을 수 없어요." 정책같은 경우 버튼의 렌더링 여부에 따라 달라져요. "담기"와 "장바구니 담기"를 구분하기 위해서는 구분할 prop이 필요해져요. 만약 CTA에 들어갈 문구가 여러개라면 내부가 복잡해질거라고 생각했어요. 그래서 외부에서 주입하자라는 결론이 나왔고, CTA에 사용할 행동과 문구를 `action: { label: string, onClick: (product:Product) => void }`로 잡았어요.

#### (리뷰)

할인 줄은 정확하다. "세 곳 모두 켰다 → 고르는 게 아니라 규칙"이라는 판단이 이 문제의 핵심 중 하나다. (파일 이름은 `ProductCart.tsx`가 아니라 `ProductCard.tsx`.)

두 번째 문단은 **지키는 것이 아니라 고르는 것** 이야기로 흘렀다. "담기와 장바구니 담기를 구분한다"는 화면마다 고르는 글자라서 `action.label`로 간 게 맞다. 그런데 "다 팔린 상품은 담을 수 없다"는 규칙이 바꾼 뒤 **어디에 남았는지**가 빠졌다. 답은 코드에 있다. `ProductCard`가 `disabled={soldOut}`를 그대로 들고 있어서, 쓰는 쪽이 `action`만 넘기면 품절 막기는 잊을 수가 없다. 이걸 적어야 "글자는 밖에서, 규칙은 안에서"라는 나눔이 보인다.

참고 답:

> 지키는 것: 할인 줄과 품절 막기. 할인은 세 곳이 모두 켰으니 `showDiscount`를 없애고 카드가 늘 그린다. 품절 막기는 카드가 `disabled={soldOut}`로 계속 지킨다. 쓰는 쪽은 `action`으로 글자와 할 일만 넘기니, 새 화면이 버튼을 달아도 품절 막기를 빠뜨릴 수 없다.

## 다음 주에 홈에 "타임특가" 칸이 생깁니다. 사진 위에 `남은 시간 02:13:45` 띠를 두르고, 담기 대신 `오픈 알림 받기` 버튼을 답니다. 바꾸기 전 구조였다면 어디를 고쳤을까요? 지금은 어디를 고치나요?

#### 바꾸기 전 구조:

남은 시간을 판별하기 위한 `showRemainingTime`같은 prop이 추가되었을것 같고, 시간을 보여줘야하기 때문에 `remainingTime` prop까지 총 2개가 생겼을것 같아요. 그리고 오픈 알림 받기 문구를 보여주기 위해 `compact`가 아닌 다른 prop이 더 생겼을것 같아요.

#### (리뷰)

맞다. 하나만 더하면, props만 늘어나는 게 아니라 **카드 안쪽 분기**도 같이 늘어난다. 지금 시작 코드의 버튼 글자는 `compact ? '담기' : '장바구니 담기'`인데, 세 번째 글자가 오면 삼항이 겹치고 `onAddToCart` 옆에 `onNotify`도 생긴다. 고치는 파일이 `ProductCard.tsx` 하나라서, 타임특가를 위한 수정이 홈·검색·장바구니 세 화면을 모두 건드린다.

참고 답:

> `showRemainingTime`, `remainingTime`, `onNotify`, 버튼 글자를 가를 prop이 더 생긴다. 카드 안의 `compact ? … : …`도 세 갈래가 된다. 고치는 곳이 카드 하나라서 타임특가 때문에 나머지 세 화면도 다시 확인해야 한다.

#### 지금 고치는 것:

사진 위에 남은 시간이 보인다는건 `ProductThumbnail`쪽이에요. 이 컴포넌트는 이미지를 감싸는 div와 img태그를 렌더링하고, `children`으로 받아서 사용하고 있어요. 따라서 `남은 시간 02:13:45`은 `children`으로 충분히 해결될 것 같아요.

버튼에서는 `action: { label: string, onClick: (product:Product) => void }` 형태로 slot을 열어두었기 때문에, label에 "오픈 알림 받기"를 전달하면 돼요.

#### (리뷰)

사진 위 띠는 맞다. 남은 시간은 `children`으로 넣으면 되고, 카드와 `ProductThumbnail`은 고치지 않는다. 1초마다 줄어드는 시간 상태도 타임특가 칸이 갖고 있으면 되니 카드는 시간을 몰라도 된다.

버튼에 **숨은 곳이 하나** 있다. 카드는 `action`이 무엇이든 `disabled={soldOut}`를 붙인다. 이 규칙은 원래 "다 팔린 상품은 **담을** 수 없다"였는데, `오픈 알림 받기`는 담기가 아니다. 아직 열리지 않은 타임특가 상품의 재고가 0으로 내려오면 알림 버튼이 막혀 버린다. label만 바꾸면 된다고 생각하면 바로 이 버그가 난다.

그래서 이 요구가 오면 먼저 "품절이면 막는다는 게 **담기 버튼의 규칙**인가, **모든 버튼의 규칙**인가?"를 정해야 한다. 담기 규칙이라면 `action`은 담기 전용으로 두고 알림 버튼은 다른 자리로 받거나, 쓰는 쪽이 `disabled`를 직접 정하게 하는 식으로 바뀐다. 지금 미리 바꿀 필요는 없다. 오늘의 `action`은 오늘의 세 화면(모두 담기)에는 맞는 모양이다.

참고 답:

> 남은 시간 띠는 `ProductThumbnail`의 `children`으로 넣는다. 카드는 고치지 않는다.
>
> 버튼은 `label`만 바꾸면 될 것 같지만, 카드가 품절이면 어떤 버튼이든 막는다. 알림 받기는 담기가 아니라서 품절이어도 눌려야 할 수 있다. 품절 막기가 담기만의 규칙인지 먼저 정하고, 그에 맞춰 `action`의 모양을 고친다.

### (리뷰) 다음에 비슷한 문제를 볼 때

1. **"이 boolean을 끄는 곳이 있나?"** 쓰는 곳 모두가 켜고 있으면 고르는 게 아니라 규칙이다. `showDiscount`를 이렇게 찾았다.
2. **"이 prop 하나가 몇 가지를 고르나?"** `compact`처럼 사진과 글자를 함께 고르는 prop은 자리별로 쪼갠다.
3. **"이 규칙을 어디서 판정하나?"** 슬롯으로 열어도 판정(`stock === 0`)은 한 곳에 둔다. 띠를 그릴지는 쓰는 쪽이 골라도, "품절이란 무엇인가"까지 쓰는 쪽마다 쓰게 하지 않는다.
