# 풀이 기록 · 적금 만기 금액 계산하기

답은 질문마다 2~3줄이면 충분합니다.

> 상황: 만기에 받는 돈은 계산기, 기간별 비교 시트, 가입 확인 세 화면에 나옵니다. 계산기는 세후 이자를, 시트는 만기 금액만을, 가입 확인은 세전 이자와 세금을 따로 보여 줍니다.

## 계산을 꺼낸 함수는 무엇을 받아서 무엇을 돌려주나요? 세 화면이 필요한 값이 다른데 그 모양으로 정한 이유는 무엇인가요?

```ts
function calculateSavingsMaturity(
  monthlyAmount: number,
  months: number,
  annualRate: number,
): {
  principal: number
  interest: number
  tax: number
  afterTaxInterest: number
  maturityAmount: number
}
```

`calculateSavingsMaturity(monthlyAmount: number, months: number, annualRate: number)` 함수에서 월 납입액, 개월수, 상품 이자율을 넣으면 원금, 세전 이자, 이자에 붙는 세금, 세후 이자, 만기에 받는 돈을 받도록 함수를 설계했어요. 세 화면에서 필요한 값은 다르지만, 하나의 함수에 포함한 이유는 세후 이자, 만기 금액, 세전 이자를 알려면 `monthlyAmount`, `months`, `annualRate`를 모두 알아야했어요. 각각의 함수를 만드는것보다 하나의 함수가 필요로하는 값들을 반환하면 쉽게 꺼내 쓸 수 있다고 생각했어요.

### (리뷰)

함수 모양은 잘 정했어요. 세 화면이 필요한 값을 모두 돌려주고, 화면은 필요한 것만 꺼내 써요.

다듬을 곳은 **이유**예요. "세 값을 알려면 세 입력이 모두 필요해서"는 맞는 말이지만, 이것만으로는 하나로 묶을 이유가 되지 않아요. 입력이 같아도 함수 세 개로 나눌 수 있거든요. 묶는 이유는 **나눴을 때 무슨 일이 생기는지**로 말하면 드러나요.

값마다 함수를 따로 만들었다면 이런 모양이에요.

```ts
calculateInterest(monthlyAmount, months, annualRate) // 세전 이자
calculateInterestTax(interest) // 세금
calculateMaturityAmount(principal, interest, tax) // 만기 금액
```

공식은 함수 안에 들어갔지만, 화면은 이 셋을 **순서대로 이어서** 불러야 해요.

```ts
// SavingsHome.tsx
const principal = monthlyAmount * months
const interest = calculateInterest(monthlyAmount, months, annualRate)
const tax = calculateInterestTax(interest)
const maturityAmount = calculateMaturityAmount(principal, interest, tax)

// TermCompareSheet.tsx, SavingsConfirm.tsx에도 같은 네 줄
```

"이자를 구하고, 그걸로 세금을 구하고, 둘로 만기를 구한다"는 순서가 세 화면에 복사돼요. 기획이 "이자 중 1만 원까지는 세금을 안 매겨요"처럼 세금을 구하는 방식을 바꾸면 세 화면을 다 열어야 하고, 하나라도 빠뜨리면 화면마다 만기 금액이 달라져요. 고치기 전 `TermCompareSheet`가 공식을 한 줄로 줄여 따로 쓰던 게 바로 이 상태였어요.

`calculateSavingsMaturity` 하나로 묶으면 이 순서가 함수 안에 한 번만 있어요. 같은 변경이 와도 그 함수 하나만 고치면 세 화면이 같이 바뀌어요. 공식만 꺼내면 반쯤 꺼낸 거고, **공식을 이어 붙이는 순서까지** 꺼내야 세 화면이 어긋나지 않아요.

참고 답:

> 월 납입액, 기간, 연 금리를 받아 넣는 돈 합계, 세전 이자, 세금, 세후 이자, 만기 금액을 한꺼번에 돌려줘요. 이 값들은 "이자 → 세금 → 만기 금액" 순서로 이어서 계산돼요. 값마다 함수를 나누면 화면마다 이 순서를 각자 이어 붙여야 해서, 세금을 구하는 방식이 바뀔 때 세 화면을 다 고쳐야 하고 하나라도 빠뜨리면 금액이 어긋나요. 그래서 순서까지 한 함수에 넣고, 화면은 필요한 값만 꺼내 쓰게 했어요. 비교 시트는 만기 금액 하나만 쓰지만, 나머지를 같이 계산하는 비용은 거의 없어요.

하나 덧붙이면, 가입 확인 화면은 이 함수를 부르지 않고 `SavingsHome`이 계산한 결과를 params로 받아요. 이것도 수정이 전파되는 방법이에요. 가입 확인은 계산기가 계산한 값을 그대로 보여 주니, 규칙이 바뀌면 계산기를 따라 바뀌어요. 다만 params는 계산 함수를 대신하지 못해요. 비교 시트는 지금 고르지 않은 기간의 금액까지 보여 줘야 해서, 계산기가 넘겨줄 값이 없고 직접 계산해야 하거든요. 그래서 계산 함수가 원본이고, params는 그 결과를 한 화면에 실어 나르는 방법이에요. 가입 확인을 이렇게 한 이유도 한 줄 있으면 좋아요.

## 함수로 꺼내지 않고 컴포넌트 안에 그대로 둔 계산이나 규칙이 있나요? 있다면 왜 거기 뒀나요?

> 예: 빈칸인지 확인하기, 입력에서 숫자만 남기기, 고른 기간을 못 찾았을 때 쓸 기간 정하기. 모두 꺼냈다면 무엇을 보고 꺼냈는지 적어도 됩니다.

`invalid={amountText !== '' && !isAmountValid}` 해당 부분은 함수로 따로 분리하지 않고 인라인으로 작성했어요. 왜냐하면 유효하지 않으면, `errorMessage`를 보여주기 위함이에요. 즉 화면 관련 정책이라고 판단했고, 만약 함수로 분리되었다면, 파일을 오가는 비용이 더 들거라고 생각했어요. jsx에서는 UI를 그리고 연산 자체가 간단하여 직관적이라고 생각했어요

### (리뷰)

잘 골랐어요. 이 `amountText !== ''`는 상품 규칙이 아니라 **화면이 에러를 언제 보여 줄지**의 결정이에요. 그래서 컴포넌트에 두는 게 맞아요.

바로잡을 사실이 하나 있어요. 에러를 보여 주는 건 `!isAmountValid` 쪽이에요. `amountText !== ''`는 반대로 **빈칸일 때는 유효하지 않아도 에러를 아직 안 보여 주는** 역할이에요. 화면에 막 들어온 사람에게 빨간 글씨를 띄우지 않으려는 거죠.

이유도 "파일을 오가는 비용", "간단해서"보다 **무엇이 바뀌면 여기를 고치나**로 쓰면 더 단단해져요. 상품 한도가 바뀌면 `savings.ts`를 고치고, "입력을 마친 뒤에만 에러를 보여 주자" 같은 화면 결정이 바뀌면 여기를 고쳐요. 바뀌는 이유가 다르니 사는 곳도 달라요.

참고 답:

> `invalid`의 `amountText !== ''`는 컴포넌트에 남겼어요. 빈칸일 때는 범위 밖이어도 에러를 보여 주지 않겠다는 화면의 결정이라서요. 상품 한도가 바뀔 때가 아니라 에러를 보여 주는 시점이 바뀔 때 고치는 코드라, 상품 규칙을 모은 `savings.ts`가 아니라 그걸 그리는 `SavingsHome`에 두었어요.

## (리뷰) 다음에 비슷한 문제를 볼 때

"계산을 꺼내자" 문제는 이 순서로 보면 돼요.

**1. 같은 공식이 몇 군데 있나?**

화면 파일을 열고 `Math.floor`, `* 0.154`처럼 숫자를 다루는 줄을 찾아요. 오늘은 같은 이자 공식이 세 화면에 있었어요. 특히 `TermCompareSheet`에는 한 줄로 줄인 공식이 따로 있었어요. 이걸 찾은 건 혼자 잘 했어요.

**2. 이건 왜 바뀌나? 기획 때문인가, 화면 때문인가?**

꺼낼지 남길지는 이 질문 하나로 갈라요.

- 기획이 정한 것(금리, 세율, 한도) → 계산 규칙 파일(`savings.ts`)
- 보이는 방식(쉼표, "연 3.5%") → `utils/format.ts`
- 화면이 언제 무엇을 보여 줄지(빈칸일 때 에러 숨기기) → 컴포넌트

오늘 두 번째 답이 바로 이 판단이었어요.

**3. 이름은 돌려주는 것으로 짓는다**

오늘 가장 오래 막힌 곳이 이름이었어요. 공식 세 개면 거의 다 풀려요.

- 계산한 값을 돌려준다 → `calculate…`
- 맞는지 아닌지를 돌려준다 → `is…`
- 화면에 보일 글자를 돌려준다 → `format…`

단어는 `knowledge.md` 용어집에서 고르면 돼요.
