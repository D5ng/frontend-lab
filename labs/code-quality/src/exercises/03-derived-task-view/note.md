## 목적

사용자가 목록을 검색 및 필터로 조회할 수 있어야 한다

## 사용자 행동

- 사용자가 검색어를 입력한다
- 사용자가 상태 필터를 선택한다
- 사용자가 할 일의 완료 여부를 변경한다
- 사용자가 완료된 할 일을 정리한다

## 사용자 행동에 따른 UI 변화

- 검색어나 필터가 변경되면 두 조건에 만족하는 할 일 목록을 보여준다.
  - 목록이 비어있으면 다음 행동을 선택할 수 있는 빈 상태를 보여준다
- 할 일의 완료 상태가 변경되면 전체, 할 일, 완료 개수가 업데이트 된다.
- 완료한 일을 정리하면 완료 항목을 제거하고 개수, 진행률, 목록이 업데이트 된다.
- 정리 후 제거된 할 일 개수를 안내한다.
- 완료한 일이 없으면 버튼이 비활성화 된다.

### 화면이 기억해야 할 정보

- 할 일 목록
- 필터(전체, 할 일, 완료)
- 검색어
- 정리 피드백 안내

## 설계 판단 과정

### 책임

`Problem` 컴포넌트의 문제점:

- UI 렌더링
  - 오늘의 진행 상황
  - 검색 및 필터
  - 할 일 목록
- 상태 관리
- 도메인 로직
- 사용자 행동 처리
- 조회 / 필터 로직
- 결과 피드백

컴포넌트가 너무 많은 관심사를 책임지고 있다. 하나의 컴포넌트가 많은 관심사를 책임지게되면, "내가 필요로하는 로직"을 파악하기가 어려워 가독성이 떨어지고 인지부하가 올 수 있다.
