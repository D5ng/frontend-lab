## 목적

사용자는 행사 정보를 임시 저장하거나, 게시할 수 있다.

## 정책

- 행사 유형을 변경해도 기존 데이터가 유실되면 안된다
- 임시 저장은 입력값이 비어있어도 가능하다
- 게시하기는 행사에 필요한 정보를 필수로 입력해야 한다
- 사용자 행동 검증 시 성공, 실패에 대한 안내해야 한다
- 현재 처리 중인 상태라면 다른 행동을 취할 수 없다

## 화면이 알아야하는 정보

- 데이터: 행사 유형, 제목, url 또는 주소
- 처리 상태: 게시 중인지, 임시 저장 중인지, 현재 처리 중이 아닌지
- UI 피드백: 성공, 실패, 폼 검증 시 안내 문구

## 책임 설계

행사에 필요한 데이터: 유형, 제목, 온라인 URL, 오프라인 주소
사용자 행동 흐름: 임시 저장 및 게시하기, 결과 안내, 현재 처리 상태
게시 정책: 행사 데이터를 기준으로 유효성 검사
