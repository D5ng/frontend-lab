## 목적

사용자는 행사 정보를 임시 저장하거나 게시할 수 있다.

## 요구사항과 정책

- 행사 유형을 변경해도 온라인 URL과 오프라인 장소는 모두 유지된다.
- 임시 저장은 입력값이 비어 있어도 가능하다.
- 게시는 제목과 현재 행사 유형에 필요한 정보를 입력해야 한다.
- 처리 중에는 입력값 변경, 유형 변경, 임시 저장, 게시를 할 수 없다.
- 검증 실패와 요청 성공·실패 결과를 사용자에게 안내한다.

## 설계 판단 과정

### 화면이 기억해야 할 정보:

- 행사 작성 정보
- 요청 상태
- 결과 피드백

#### 게시 가능 여부는 행사 작성 정보만으로 판단할 수 있다.

- 행사 등록을 위한 필수 입력값 규칙은 도메인 정책이다
- 행사 작성 정보를 입력받아, 검증을 하는 역할이기에 책임을 분리했다

#### 임시 저장과 게시 요청은 행사 작성 정보, 처리 상태, 결과 피드백을 함께 변경한다.

- 따라서 행사 등록 흐름 훅에서 관리한다.

#### 화면은 상태를 표시하고 사용자 입력을 전달하면 된다.

- UI가 표시해야 하는 정보는 행사 작성 정보, 요청 상태, 결과 피드백이다.

## 책임 설계

- `model/eventForm.ts`
  - 행사 작성 정보의 타입과 요청 전 데이터 정리를 담당한다.

- `policy/publishValidationMessage.ts`
  - 게시 가능 여부를 판단하고 실패 안내 문구를 반환한다.

- `hooks/useEventRegistration.ts`
  - 행사 작성 정보, 요청 상태, 결과 피드백을 관리한다.
  - 임시 저장과 게시 요청 흐름을 조율한다.

- `Problem.tsx`
  - 화면을 렌더링하고 사용자 입력을 훅에 전달한다.

## 검증

- 행사 유형 전환 후 URL과 장소가 유지되는지 테스트했다.
- 빈 값 임시 저장, 게시 검증, 요청 중 중복 실행 방지를 테스트했다.
- 테스트, 린트, 타입 검사와 빌드를 통과했다.
