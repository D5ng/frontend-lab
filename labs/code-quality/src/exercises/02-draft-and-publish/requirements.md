# Exercise 02 요구사항: 임시 저장과 게시

## 목표

모임 운영자가 모바일 행사 관리 서비스에서 새 행사의 기본 정보를 작성할 수 있어야 한다.
작성 중인 내용을 잃지 않도록 임시 저장할 수 있고, 참여자에게 공개할 준비가 되면 게시할 수 있다.

이 실습에서는 외부 API 대신 비동기 요청 함수를 사용한다. 요청 구현 자체가 아니라, 화면 상태·검증·요청·결과 안내의 책임을 판단하는 것이 범위다.

## 화면 맥락

- 사용자는 `행사 만들기`의 2단계 중 첫 화면인 `기본 정보` 화면에 진입한다.
- 모든 화면은 너비 375px 뷰포트를 기준으로 구현하고 검증한다.
- 상단에는 현재 화면의 제목과 1 / 2 진행 상태를 보여 준다.
- 본문은 행사 정보 입력에만 집중하며, 데스크톱 레이아웃은 고려하지 않는다.
- 하단에는 `임시 저장`과 `게시하기`를 세로로 배치한다. 게시하기는 사용자가 마지막에 선택하는 주 행동이다.
- UI 구현은 Montage 컴포넌트와 토큰을 우선 사용한다. 단, 화면을 구성하는 방식이 학습 주제의 정답을 미리 드러내서는 안 된다.

## 행사 입력

- 사용자는 행사 유형으로 온라인 또는 오프라인 중 하나를 선택할 수 있다.
- 처음 선택된 유형은 온라인이다.
- 모든 행사에는 제목 입력란이 있다.
- 온라인 행사에는 온라인 접속 URL 입력란을 보여 준다.
- 오프라인 행사에는 오프라인 장소 입력란을 보여 준다.
- 유형을 전환해도 온라인 접속 URL과 오프라인 장소에 이미 입력한 값은 각각 보존한다.

## 임시 저장

- 사용자는 제목, URL, 장소가 비어 있어도 임시 저장할 수 있다.
- 임시 저장 요청이 성공하면 `임시 저장했어요.`를 보여 준다.

## 게시

- 사용자가 게시하기를 누르면 아래 순서로 입력값을 확인한다.
  1. 제목이 비어 있으면 `행사 제목을 입력해 주세요.`를 보여 준다.
  2. 온라인 행사인데 접속 URL이 비어 있으면 `온라인 접속 URL을 입력해 주세요.`를 보여 준다.
  3. 오프라인 행사인데 장소가 비어 있으면 `오프라인 장소를 입력해 주세요.`를 보여 준다.
- 공백만 입력한 값은 비어 있는 값으로 취급한다.
- 검증에 실패하면 게시 요청을 실행하지 않는다.
- 게시 요청이 성공하면 `행사를 게시했어요.`를 보여 준다.

## 요청 처리

- 임시 저장 또는 게시 요청이 진행 중인 동안에는 입력, 유형 변경, 두 작업 버튼을 모두 사용할 수 없다.
- 요청이 실패하면 `작업을 완료하지 못했어요. 다시 시도해 주세요.`를 보여 준다.
- 결과 안내는 화면에서 확인할 수 있어야 한다.

## 범위 밖
