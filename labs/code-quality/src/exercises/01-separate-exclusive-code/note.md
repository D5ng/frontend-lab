## 사용자 흐름

1. 사용자가 상품 수령 요청 페이지에 진입한다
2. 사용자가 배달 또는 매장 픽업을 선택한다
3. 선택한 값에 필수 입력값을 작성한다
4. 요청하기를 누른다
5. 필수 입력값을 작성하지 않으면 안내 문구를 보여준다
6. 유효성 검증되면 결과 안내 문구를 보여준다

## 보존 데이터

- 상품 수령 방법(배달, 매장 픽업)
- 배달인 경우 주소 입력
- 매장 픽업인 경우 픽업 매장 입력
- 결과 안내 문구

## 정책

- 선택된 값이 배달이라면 주소를 반드시 작성해야 한다
- 선택된 값이 매장이라면 픽업 매장을 반드시 작성해야 한다
- 선택된 값을 변경하더라도 수령 방법에 따른 필수 입력값이 보존되어야 한다
- 필수 입력값을 입력하지 않아도 버튼은 활성화되어야 한다
- 유효성 검사는 요청하기를 누른 시점에 한다

## 현재 구조

<Problem /> 컴포넌트에서 다음과 같은 책임을 맡고있다:

- UI 렌더링
- 상태(상품 수령 방법, 수령 방법에 따른 필수 입력값, 결과 안내 문구)
- `handleSubmit` 폼 검증 및 결과 처리

## 내가 생각한 책임

- UI 렌더링과 비즈니스 로직을 분리
  - UI와 비즈니스 로직이 함께 있으면, 내가 읽지않아도될 코드도 섞여있어 인지부하가 올 수 있다. UI는 상태를 기반으로 렌더링에 집중하면되고, 비즈니스 로직은 도메인 관련한 정책을 담당하기에 서로 역할이 다르다.

## 내 생각

상품 수령 방법을 변경해도 입력된 값은 보존되어야 한다:

- 입력된 값이 사라지는 경우는 무엇일까? 조건에 따라 UI가 언마운트 또는 마운트 된다. 관리해야하는 상태가 해당 UI 컴포넌트에 있으면 언마운트될 때 상태도 사라지게 된다. 따라서 초깃값으로 변경된다.
- 그렇다면 상태는 가장 가까우면서 공통으로 소유하고있는 상위 컴포넌트에서 관리하는게 맞을것 같고, UI만 분리하면 될 것 같다.

전반적인 흐름:

수령 방법 선택 -> 선택한 값에 따라 사용자 입력 -> 요청하기 -> 유효성 검증
