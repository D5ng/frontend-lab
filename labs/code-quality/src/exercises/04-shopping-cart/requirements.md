# Exercise 04 요구사항: 장바구니

## 이 실습의 방식

처음부터 완성된 설계를 고르는 실습이 아니다. 가장 쉬운 기능 하나로 시작해 단계마다 기능을 하나씩 덧댄다.

- 다음 단계의 요구사항은 지금 단계를 끝낸 뒤에 공개한다. 미리 대비하지 않는다.
- 코드를 나누거나 합치는 것은 **그 단계의 변경이 이유를 줄 때만** 한다.
- 이전 단계의 판단을 뒤집어도 된다. 판단이 바뀐 이유를 남기는 것이 이 실습의 결과물이다.

## 1단계: 수량 조절

### 목표

사용자는 장바구니에 담은 상품 하나의 수량을 정하고, 얼마를 내게 되는지 확인한다.

### 화면

- 너비 375px 모바일 화면이다.
- 상품은 `제주 햇감귤 3kg` 하나이고 가격은 18,900원이다.
- [Problem.tsx](./Problem.tsx)에 화면은 이미 그려져 있고 동작만 없다.

### 규칙

- 수량은 1개에서 시작한다.
- `수량 늘리기`를 누르면 1개 늘어난다.
- `수량 줄이기`를 누르면 1개 줄어든다.
- 수량은 1개보다 줄일 수 없다. 수량이 1개일 때 `수량 줄이기`를 누를 수 없다.
- 총 결제 금액은 가격 × 수량이며 `56,700원`처럼 천 단위 쉼표와 `원`으로 표시한다.

### 범위 밖

- 상품 삭제, 여러 상품
- 주문하기
- 서버 요청, 저장

### 제약

**`Problem.tsx` 한 파일 안에서 구현한다.** 훅, 컴포넌트, 함수를 다른 파일로 나누지 않는다.

## 단계마다 남길 기록

`note.md`에 단계별로 짧게 쓴다. 길게 쓸 필요는 없다.

1. **구현 전** — 이번 단계에서 화면이 기억해야 하는 것과 계산하면 되는 것
2. **구현 후** — 지금 코드가 한 곳에 모여 있어 불편한 점이 있었는가. 있었다면 그 불편은 이번 요구사항에서 왔는가, 앞으로 올 것 같은 요구사항에서 왔는가
3. **틀릴 수 있는 지점** — 지금 판단 중 다음 변경에서 흔들릴 것 같은 부분 하나
