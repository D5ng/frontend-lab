# 동네 미용실 예약

- 예상 시간: 2~3시간
- 주는 것: 사용자 목적, 화면 흐름, 기획 메모, 모의 API, **네 화면의 UI 전부**
- 주지 않는 것: 동작(상태, 요청, 규칙 계산, 화면 이동), 테스트, 폴더 구조

화면은 다 그려져 있습니다. 값은 예시로 박혀 있고, 누르는 곳은 `() => {}`로 비어 있고, 처음엔 안 보이는 상태는 주석으로 들어 있습니다. 그려진 화면 뒤에 상태와 규칙을 어떻게 놓을지가 이번 과제입니다. `screens/`는 그대로 써도, 나누거나 합치거나 옮겨도 됩니다. `App.tsx`에서 `App`을 내보내는 것만 지켜 주세요.

## 사용자의 목적

> 단골 미용실에서 원하는 디자이너에게, 받고 싶은 시술을 고르고, 가능한 시간에 예약한다.

## 화면 흐름

```text
가게 홈 ──▶ 시술 선택 ──▶ 날짜·시간 선택 ──▶ 예약 확인(바텀시트) ──▶ 예약 완료
디자이너 고르기   여러 개 선택     7일 중 하루, 30분 단위
```

## 기획 메모

> 기획자가 슬랙에 남긴 메모를 그대로 옮겼다고 생각해 주세요.

- 디자이너마다 할 수 있는 시술이 달라요. 가게 홈에서 디자이너를 고르면 그 사람이 하는 시술만 보여 주세요.
- 시술은 여러 개 고를 수 있어요. 걸리는 시간은 모두 더해요. 커트 30분에 염색 90분이면 2시간이에요.
- 염색, 펌처럼 같은 종류 시술은 하나만 고를 수 있어요. 다른 염색을 누르면 바꿔 주세요.
- 시술 선택 화면 아래에는 총 금액과 총 시간이 계속 보여야 해요.
- 날짜는 오늘부터 7일만 보여 주세요. 디자이너가 쉬는 요일은 고를 수 없어요.
- 시간은 30분 간격으로 보여 주는데, 고른 시술이 마감 전에 끝나고 다른 예약과 안 겹치는 시간만 누를 수 있어요. 오늘이면 지금 이후 시간만요.
- 고를 수 있는 시간이 하나도 없는 날은 "이 날은 예약이 꽉 찼어요"라고 알려 주세요.
- 예약 확인에서 디자이너, 시술, 날짜, 시작과 끝 시간, 총 금액을 한 번 더 보여 주세요. 결제는 가게에서 해요.
- 예약하기를 눌렀는데 그새 다른 사람이 그 시간을 가져가면 시간 선택으로 돌아가서 다시 고르게 해 주세요. 고른 시술은 그대로 두고요.
- 시간까지 고른 뒤 뒤로 가서 시술을 바꾸는 사람이 있을 거예요. 이때 고른 시간을 어떻게 할지는 정해 주세요. **(결정과 이유를 note.md에 적는다)**

## 모의 API

모든 응답은 MSW로 0.5초 뒤에 옵니다. 모의 서버(`handlers.ts`)는 풀이 대상이 아닙니다.

```http
GET /api/assignments/salon-booking/salons/salon-1
```

```json
{
  "id": "salon-1",
  "name": "골목 헤어",
  "now": "2026-11-07T13:10:00+09:00",
  "openTime": "10:00",
  "closeTime": "20:00",
  "designers": [
    { "id": "d1", "name": "하늘 원장", "dayOffs": ["MON"], "serviceIds": ["cut", "color-basic", "color-bleach", "perm-digital"] },
    { "id": "d2", "name": "도윤 실장", "dayOffs": ["TUE", "WED"], "serviceIds": ["cut", "perm-setting", "clinic"] }
  ],
  "services": [
    { "id": "cut", "name": "커트", "category": "cut", "minutes": 30, "price": 20000 },
    { "id": "color-basic", "name": "기본 염색", "category": "color", "minutes": 90, "price": 70000 },
    { "id": "color-bleach", "name": "탈색", "category": "color", "minutes": 120, "price": 110000 },
    { "id": "perm-digital", "name": "디지털 펌", "category": "perm", "minutes": 150, "price": 130000 },
    { "id": "perm-setting", "name": "셋팅 펌", "category": "perm", "minutes": 120, "price": 100000 },
    { "id": "clinic", "name": "두피 클리닉", "category": "care", "minutes": 40, "price": 35000 }
  ]
}
```

`now`가 지금 시각입니다. 기기 시계가 아니라 이 값을 기준으로 "오늘"과 "지금 이후"를 정합니다.

```http
GET /api/assignments/salon-booking/salons/salon-1/bookings?designerId=d1&date=2026-11-07
```

```json
[
  { "start": "13:30", "end": "15:00" },
  { "start": "17:00", "end": "18:30" }
]
```

그 디자이너의 그날 이미 잡힌 예약입니다. 예약이 없으면 빈 배열입니다.

```http
POST /api/assignments/salon-booking/salons/salon-1/bookings
{ "designerId": "d1", "serviceIds": ["cut", "color-basic"], "date": "2026-11-07", "start": "15:00" }
```

| 응답  | 뜻                                   |
| ----- | ------------------------------------ |
| `201` | `{ "id": "b-123" }` 예약 완료        |
| `409` | `{ "code": "SLOT_TAKEN" }` 그새 마감 |
| `500` | 서버 오류. 다시 시도할 수 있다       |

화면에서 확인하는 법

- **409**: 16:00에 시작하는 예약은 항상 그새 마감됩니다.
- **꽉 찬 날**: 하늘 원장의 11월 8일은 하루 종일 예약이 차 있습니다.
- **500**: 화면에서는 재현되지 않습니다. 테스트에서 핸들러를 `server.use(...)`로 덮어 확인합니다.

시술 시간이 30분 단위가 아닐 수 있다는 점(두피 클리닉 40분)은 일부러 넣었습니다.

## 해야 할 일

1. **구현 전에** `note.md`에 요구사항 분석을 쓴다.
2. 그려진 네 화면에 동작을 붙여 끝까지 완성한다. 불러오는 중, 실패, 꽉 찬 날, 409 마감을 포함한다.
3. 행동 테스트를 직접 쓴다. 최소한 아래 세 장면은 테스트로 고정한다.
   - 시술을 바꾸면 고를 수 있는 시간이 바뀐다.
   - 쉬는 요일과 꽉 찬 날을 고를 수 없다.
   - 409가 오면 시술은 남은 채로 시간 선택으로 돌아간다.
4. 직전 드릴 여섯 번 동안 쌓은 `docs/나의 기준.md`에서 실제로 쓴 기준에 표시하고, 쓰지 못한 기준은 왜 그랬는지 한 줄 남긴다.

```bash
pnpm dev:assignments
pnpm --filter @frontend-lab/assignments test
```

## 그려 둔 화면

| 화면 / 상태          | 파일                | 그려 둔 UI                                                           |
| -------------------- | ------------------- | -------------------------------------------------------------------- |
| 화면 틀과 이동       | `App.tsx`           | 네 화면을 Stackflow 활동으로 등록. 이동은 연결되어 있지 않다         |
| 가게 홈              | `SalonHome.tsx`     | 디자이너 `ListButtonItem`, `Avatar`, 휴무 `Badge`                    |
| 시술 선택            | `SalonServices.tsx` | 종류별 `ListHeader` + `ListCheckItem`, 하단 고정 총 시간·금액과 버튼 |
| 날짜·시간 선택       | `SalonSchedule.tsx` | 7일 `ChipTabs`, 30분 단위 `Chip.RadioItem`, 하단 고정 요약과 버튼    |
| 예약 확인            | `SalonSchedule.tsx` | `BottomSheet`. 예약하기 버튼으로 열린다                              |
| 예약 완료            | `SalonDone.tsx`     | 완료 문구와 예약 요약                                                |
| 불러오는 중 (주석)   | 홈, 날짜·시간       | `Skeleton`                                                           |
| 불러오기 실패 (주석) | 홈, 날짜·시간       | `Callout tone="critical"`                                            |
| 꽉 찬 날 (주석)      | 날짜·시간           | `Callout tone="neutral"`                                             |
| 그새 마감 (주석)     | 날짜·시간           | `Callout tone="warning"`                                             |
| 예약 실패 (주석)     | 예약 확인 시트      | `Callout tone="critical"`                                            |

- 시트가 열리고 닫히는 것, 칩이 눌린 모양처럼 SEED 컴포넌트가 스스로 하는 반응은 그대로 두었습니다. 그 값으로 계산하고 요청하는 일만 비어 있습니다.
- 날짜·시간 화면의 비활성 시간과 휴무일 표시는 모양을 보여 주는 예시입니다. 어떤 시간을 막을지는 기획 메모대로 정합니다.
- 다른 화면을 미리 보려면 `App.tsx`의 `initialActivity`를 잠깐 바꿉니다.

## 용어집

| 뜻                    | 영어                     |
| --------------------- | ------------------------ |
| 시술                  | `service`                |
| 걸리는 시간           | `duration`, `minutes`    |
| 영업 시작 / 마감      | `openTime` / `closeTime` |
| 휴무 요일             | `dayOff`                 |
| 예약 가능한 시간      | `availableSlot`          |
| 겹치다                | `overlap`                |
| 그새 마감 (선점 충돌) | `conflict`, `slotTaken`  |
| 시술 종류             | `category`               |
