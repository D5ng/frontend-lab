## 375 × 812 실제 브라우저 검증

공통 Daily 앱의 오늘 hash에서 실제 MSW 요청과 사용자 조작으로 확인했습니다. 전용 테스트 페이지나 DOM 상태 주입으로 대체하지 않았습니다.

- 초기: 전체 선택, 기존 3개 목록, 적용 버튼 비활성.
- 생활용품·도서 해제: 선택 요약만 바뀌고 기존 3개 목록과 적용 조건 유지.
- 첫 적용: 진행 안내, 버튼 disabled, 기존 결과 유지 → HTTP 503 후 오류와 기존 적용 조건/3개 유지.
- 재시도 직후 도서를 다시 선택: 대기 중 선택이 바뀌고 추가 적용은 비활성. 성공 후 **적용=가구, 선택=가구+도서, 결과=가구 2개**, 버튼 재활성.
- 가구 해제 후 도서만 적용: **0개, 적용=도서**, 다른 카테고리 선택 안내와 동일 조건 버튼 비활성.
- 도서도 해제 후 적용: 빈 선택 오류. Space로 가구 체크하면 오류 해소와 선택 갱신.
- DOM 측정: viewport/문서 scrollWidth 모두 375. 초기·편집·로딩·실패·성공·빈 결과·빈 선택 오류에서 가로 넘침 없음.
- 선택 행 343 × 48px, 주요 버튼 높이 52px. 세 체크박스 접근성 이름과 그룹 이름/설명 연결 확인. label 텍스트 클릭과 키보드 Space로 실제 선택 가능.
- 브라우저 error/warn 로그 없음(확인 시점 기록). 모의 503 자체는 의도된 시나리오입니다.
