# 새 목록과 늦게 도착한 더보기

- 유형: 직접 구현형
- 예상 시간: 35~40분
- 사용자 목표: 동네 나눔 글을 이어서 읽고, 새로고침한 목록에 이전 페이지가 끼어들지 않게 한다.

## 핵심 설계 질문

**한 목록의 다음 페이지와 새로 시작한 목록을 구분하는 책임을 어디에 둘까요?**

`starter.tsx`의 `FeedPager`에서 직접 구현하세요. 화면과 HTTP 모의 API는 제공하지만 상태 전이·중복 제거·응답 반영 로직은 제공하지 않습니다. `FeedView`의 props는 표현 계약이며 정답 상태 구조나 훅 개수를 지정하지 않습니다. 함수 주입 `loadPage`를 유지하세요.

## 요구사항

1. 진입하면 `loadPage(null)`로 첫 페이지를 조회합니다. 첫 조회 또는 새로고침은 기존 목록·cursor·오류를 즉시 비우고 Skeleton과 `나눔 목록을 불러오고 있어요.`를 표시합니다. 이때 새로고침·더보기는 잠깁니다. 자동으로 다음 페이지까지 조회하지 않습니다.
2. 조회 성공은 받은 순서로 글을 표시합니다. `nextCursor`가 null이면 더보기를 잠그고, 글이 있으면 `모든 나눔 글을 확인했어요.`를 표시합니다. 빈 첫 페이지는 오류가 아닙니다. `아직 나눔 글이 없어요. 나중에 새로고침해 주세요.`를 표시합니다. 빈 첫 페이지의 nextCursor는 null인 API 계약입니다.
3. 더보기는 현재 nextCursor로 한 번 요청합니다. 기존 글을 유지하며 `다음 페이지를 불러오고 있어요.`와 버튼 스피너를 표시하고 더보기는 잠급니다. **새로고침은 더보기 중에도 가능합니다.** 성공한 페이지의 새 ID만 뒤에 추가하고 응답의 nextCursor로 진행합니다. 동일 페이지 내부와 페이지 사이 모두 ID 중복을 제거하고 최초 등장한 글·순서·내용을 유지합니다.
4. 첫 조회 실패는 빈 목록·더보기 비활성을 유지하고 `목록을 불러오지 못했어요. 새로고침해 주세요.`를 표시합니다. 다음 페이지 실패는 기존 글과 실패한 cursor를 보존하고 `다음 페이지를 불러오지 못했어요. 다시 불러와 주세요.` 및 `다음 페이지 다시 불러오기` 버튼을 표시합니다. 재시도는 **실패한 cursor**로 요청합니다. 재시도 시작 시 오류를 지웁니다. 성공할 때까지 cursor를 미리 다음 값으로 넘기지 않습니다.
5. 새로고침은 첫 페이지부터 새로운 목록을 시작합니다. 이전 더보기의 **성공·실패·완료를 모두 무시**합니다. 이전 성공이 글을 끼워 넣거나 cursor를 바꾸면 안 되고, 이전 실패가 새 화면을 오류로 만들거나 이전 완료가 새 조회·더보기의 진행 표시를 끝내면 안 됩니다. cursor 문자열이 같아도 이전 목록의 요청을 새 목록에 재사용하지 않습니다. 실제 요청 취소는 범위 밖입니다.

실행 예: 첫 페이지 성공 → 더보기 요청 → 목록 새로고침 → 새 첫 페이지 성공 → 새 더보기 요청 → 이전 더보기 실패/성공 도착. 마지막 응답은 현재 목록·오류·버튼 진행 상태에 영향이 없어야 합니다.

## API·입력·실행 환경

`LoadPage`는 `(cursor: string | null) => Promise<{ items: Post[]; nextCursor: string | null }>`입니다. null은 첫 페이지, cursor는 서버가 주는 불투명한 다음 페이지 위치입니다. 입력 폼·필터는 없습니다. 실제 목록은 서버 응답으로만 얻습니다.

기존 공통 HTTP 클라이언트와 MSW를 사용합니다. 날짜 폴더의 `handlers.ts`는 공통 glob에 자동 등록됩니다. 첫 페이지 0.6초·2개 → next-1 1.6초·첫 요청만 실패, 재시도는 앞 페이지의 중복 글 1개+새 글 1개 → next-2 0.6초·새 글 1개, 종료. 세션별 실패 횟수는 화면 재진입 시 초기화되며 새로고침 버튼은 세션을 새로 만들지 않습니다. 실제 외부 서버 저장은 없고 개발자 도구에서는 MSW가 가로챈 요청을 볼 수 있습니다. API가 응답을 주더라도 화면에 반영할지는 실습자가 결정합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev:daily
pnpm --filter @frontend-lab/daily-frontend exec vitest run problems/2026-10-13-feed-pages/Problem.spec.tsx
pnpm --filter @frontend-lab/daily-frontend build
```

Daily의 오늘 항목 또는 `#2026-10-13-feed-pages`로 진입합니다. `describe.skip('직접 구현할 목록 행동', ...)`을 `describe`로 바꾸어 풀이를 확인하세요. 활성 UI·HTTP 검사는 준비물 검증이지 풀이 완료가 아닙니다.

## 화면 맥락과 SEED

나눔 목록 → 더보기의 인라인 흐름입니다. 상세·예약·거래 시작은 범위 밖이므로 공식 `List/ListItem`은 비클릭 정보 행입니다. 새로고침은 공식 ActionButton neutralWeak large, 더보기는 neutralSolid large로 위계를 줍니다. 첫 목록 로딩은 공식 Skeleton neutral·텍스트 lineHeight 토큰으로 행 윤곽만 표현하고 버튼 스피너를 겹치지 않습니다. 더보기는 기존 목록을 유지하고 공식 버튼 loading으로 나타냅니다. 오류는 공식 Callout critical·alert로 남깁니다. 성공·빈 목록·마지막 페이지는 공식 Text·status로 안내합니다. 공식 VStack/Text와 공개 x2/x4/x6 토큰을 사용합니다. 새로고침이 이전 추가 요청을 무효화하는 것은 과제의 의도이므로 더보기 중 새로고침은 잠그지 않습니다. 폼·선택 위젯·시트·Dialog는 필요하지 않습니다. 지정된 SEED 기준을 출제 스킬의 Montage 지침보다 우선합니다.

| 상태     | 표현                                                                 |
| -------- | -------------------------------------------------------------------- |
| Empty    | 나눔 글 없음과 새로고침 안내                                         |
| Loading  | 첫 페이지 Skeleton 또는 목록 유지+더보기 진행                        |
| Error    | 첫 조회·다음 조회 오류를 구분하고 해당 재시도 제공                   |
| Disabled | 첫 조회 중 두 버튼 잠금, 더보기 중 더보기만 잠금, 끝이면 더보기 잠금 |
| Success  | 받은 순서의 목록과 마지막 페이지 확인                                |

`?feed-preview=initial`, `loading`, `ready`, `more`, `error`, `moreError`, `empty`, `complete`는 **정적 렌더 검수용**이고 콜백은 비어 있습니다. 예: `/?feed-preview=more#2026-10-13-feed-pages`. 상태 전이·실제 조회가 구현된 것으로 보지 마세요. 풀이에서는 query를 지우세요.

## 완료 조건

1. 행동 테스트를 활성화해 통과하고 더보기 실패→재시도·진행 중 새로고침·늦은 응답을 화면에서도 확인합니다.
2. 현재 목록과 추가 요청의 유효 범위·cursor 소유권을 `note.md`에 직접 기록합니다. 파일·훅 개수나 중복 제거 자체는 정답이 아닙니다.
3. 직접 실행한 검증과 예상만 한 결과를 구분합니다.

범위 밖: 무한 스크롤·스크롤 복원·캐시·필터·요청 취소·목록 실시간 갱신·서버 영속 저장. [Frontend Fundamentals](https://frontend-fundamentals.com/code-quality/code/)의 네 기준은 풀이 후 설계 판단의 참고 기준입니다.

## 출제 시 검증 범위

- 최신 origin/develop 기준 관리 worktree에서 frozen lockfile 설치, 전체 lint·format·test·build(TypeScript 검사 포함) 통과. 오늘 UI·HTTP 검사 11개 통과, 직접 구현할 행동 8개는 의도적 skip입니다. Daily 전체 47개 통과·13개 skip(오늘 8개+기존 5개), code-quality 22개 통과입니다. skip은 풀이 완료가 아닙니다.
- 실제 브라우저 375×812에서 스타터·정적 상태 8개를 확인했습니다. 첫 로딩 Skeleton, 더보기 중 기존 글 유지와 새로고침 활성, 첫/추가 오류·재시도 버튼, 빈 목록·완료 안내와 비활성 상태를 확인했습니다. 버튼 접근성 이름·52px 터치 영역·공통 문제 선택기 라벨, 가로 넘침 없음(scrollWidth 375px), error/warn 로그 없음 확인. 오늘 화면에는 텍스트 입력·선택 폼이 없습니다.
- **초기 자동 조회·중복 제거·cursor 재시도·실제 더보기/새로고침 전이·늦은 성공/실패/완료 무효화는 미구현·미검증**입니다. HTTP 응답 자체의 첫/마지막 페이지·다음 페이지 실패/동일 cursor 재시도는 활성 MSW 검사로 확인했습니다. 정적 미리보기를 실제 전이로 보지 마세요. 실제 휴대폰·스크린리더 음성 출력도 미검증입니다.
- 설치본 React 2.5.1·CSS 2.8.3 및 peer CSS ^2.8.0을 확인했습니다. 설치된 공식 ui:list의 metadata React/CSS ^2.0.0과 오늘 사용하는 타입·실제 렌더는 통과했지만, **seed-design compat 전체 검사는 최신 registry ui:list 요구 CSS ^3.0.0 때문에 실패**했습니다. 설치본과 최신 registry 진단을 구분하여 기록합니다. 기존 스니펫·의존성·lockfile을 바꾸거나 검사를 우회하지 않고 이 한계와 미완성 행동을 명시한 Draft PR로 제공합니다.
