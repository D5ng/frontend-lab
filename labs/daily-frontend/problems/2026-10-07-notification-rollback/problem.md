# 하나의 알림 실패가 다른 상품을 바꾸지 않게

- 유형: 행동 보존 리팩터링
- 예상 시간: 30~40분
- 사용자 목표: 관심 상품의 가격 알림을 각각 바로 변경하고, 실패한 상품만 다시 시도한다.

## 상황과 요구사항

`starter.tsx`는 이미 동작합니다. 책상은 알림 꺼짐, 전집은 켜짐, 화분은 꺼짐으로 시작합니다. 상품별 표시값·요청 중 여부·안내 메시지가 서로 다른 곳에서 관리됩니다. 기능을 추가하거나 실패 복구를 새로 구현하는 문제가 아닙니다.

1. 상품 행을 누르면 알림과 상단 개수가 즉시 바뀝니다. 개수에는 아직 서버 응답을 기다리는 화면의 값도 포함됩니다.
2. 요청 중인 상품만 비활성화합니다. 다른 상품은 변경할 수 있고, 같은 상품의 요청은 중복 전송하지 않습니다.
3. 성공하면 해당 상품에 켬/끔 완료 안내를 표시합니다. 실패하면 해당 상품만 요청 전 값으로 복구하고 재시도 안내를 표시합니다. 다른 상품의 값과 요청 상태, 메시지는 유지합니다.
4. 재시도 시 해당 상품의 이전 안내만 지웁니다. 새 요청도 즉시 화면에 반영하고, 성공 또는 실패에 따라 같은 규칙을 적용합니다.

예: 책상을 켜고 곧바로 전집을 끕니다. 전집이 먼저 성공하고 책상이 나중에 실패하면, 두 상품 모두 꺼짐이고 전집의 성공 안내는 남습니다. 실패가 먼저 도착해도 다른 상품의 진행 상태를 지우면 안 됩니다.

## 실행 환경과 입력

저장소 루트에서 `pnpm install --frozen-lockfile`, `pnpm dev:daily`를 실행하고 오늘 문제를 선택합니다. 직접 주소의 해시는 `#2026-10-07-notification-rollback`입니다.

`api.ts`는 상품 목록과 `updateNotification({ productId, enabled }): Promise<void>`를 제공합니다. 책상의 첫 요청은 1.8초 후 실패하고 이후에는 성공합니다. 전집은 0.45초, 화분은 0.7초 후 성공합니다. 문제를 바꿨다가 돌아오면 초기화되며 실제 서버에 저장하지 않습니다.

## 완료 조건

1. 기존 요구사항과 `Problem.spec.tsx`의 모든 활성 테스트를 유지합니다. 테스트를 삭제하거나 건너뛰어 통과시키지 않습니다.
2. 상태 변경과 복구의 책임이 지금보다 이해하기 쉽게 읽히도록 재구성하고, 선택한 경계를 `note.md`에 설명합니다.
3. 서로 다른 상품을 연속 변경한 뒤 실패·재시도 과정을 화면에서 확인하고, 실제 결과를 기록합니다.

검사: `pnpm --filter @frontend-lab/daily-frontend exec vitest run problems/2026-10-07-notification-rollback/Problem.spec.tsx` 및 Daily lint/build.

## 핵심 설계 질문

**한 상품의 변경·완료·실패 복구에서 함께 바뀌는 규칙을 어디에 두면, 다른 상품을 보존한다는 약속을 쉽게 확인할 수 있을까요?**

[Frontend Fundamentals](https://frontend-fundamentals.com/code-quality/code/)의 가독성·예측 가능성·응집도·결합도를 참고하세요. 파일 수, 훅 개수, 중복 제거 자체를 정답으로 삼지 않습니다. UI 분리와 상태 재구성 중 무엇이 실제 변경 이유에 도움이 되는지 먼저 판단하세요.

## UI 구성과 확인 범위

즉시 적용되는 독립 설정이므로 SEED 공식 `ListSwitchItem`과 `Switch.Control/Thumb`을 사용합니다. 별도 저장 버튼이나 전체 선택은 없습니다. 행 전체가 터치 영역이며 입력은 상품별 이름을 갖습니다. 안내는 공식 Callout, 배치는 VStack/Text입니다. 설치된 공식 v2 스니펫을 유지하고 최신 레지스트리의 v3 스니펫으로 교체하지 않습니다. 공통 앱의 최신 `ui:list` 호환 진단은 별도 검증 결과로 안내합니다.

출제 시 오늘 행동 테스트 8개, 루트 lint·format·test·build(타입 검사 포함)를 통과했습니다. 기존 10월 2일 문제의 미완성 테스트 4개는 기존대로 건너뛰며 오늘 테스트는 전부 활성 상태입니다. Chromium 375×812에서 초기 상태, 동시 변경, 상품별 비활성화, 실패 복구, 재시도와 성공 안내를 실제 조작했습니다. 가로 넘침과 브라우저 오류가 없고 상품별 입력 이름과 375×66px 행 터치 영역을 확인했습니다. 스크린리더 음성 출력 및 다른 브라우저는 확인하지 않았습니다.

`seed-design compat`는 기존 `ui:list`의 최신 레지스트리가 CSS `^3.0.0`을 요구하여 실패합니다. 설치본은 React 2.5.1·CSS 2.8.3이며 기존 공식 스니펫의 metadata는 양쪽 `^2.0.0`을 요구합니다. 이 문제에서 사용하는 설치본 타입·빌드·실제 행동은 확인했지만 최신 레지스트리 기준 전체 호환을 통과했다고 주장하지 않습니다. 공통 패키지나 스니펫 변경은 오늘 과제 범위에 넣지 않고 Draft PR로 제공합니다.
