# 풀이 기록

리팩터링하면서 내린 결정마다 멘토가 "어떤 근거로, 왜 그렇게 했어요?"를 묻습니다. 각 항목의 **상황**은 문제나 코드에 있는 사실이고, 그 아래 질문에 본인 말로 답합니다. 꼬리 질문은 첫 답을 쓴 뒤에 읽어도 됩니다. 줄 번호는 `starter.tsx` 기준입니다.

## 1. 요약은 보이는 상품 기준일까, 선택한 상품 기준일까

**상황**: 책상(12,000원)과 화분(나눔)을 선택한 뒤 `나눔` 필터로 바꿨다. 목록에는 화분만 보인다. 동료가 "요약은 화면에 보이는 상품만 세자"며 요약 영역(115번째 줄부터 128번째 줄)의 `products`만 아래처럼 `visibleProducts`로 바꿨다. 숨겨진 선택 안내(130번째 줄부터)와 예약 요청(20번째 줄부터)은 그대로 `products`를 쓴다.

```tsx
const visibleProducts = products.filter((product) => filter === 'all' || product.price === 0)

<Text textStyle="t5Bold">선택 {visibleProducts.filter((product) => selectedIds.includes(product.id)).length}개</Text>
// 상품 금액, 상품 이름도 같은 식으로 visibleProducts에서 계산한다
```

> "이때 요약 영역에는 개수·금액·이름이 어떻게 보이고, 그 아래 숨겨진 선택 안내는 뭐라고 말해요? 이 상태에서 예약 버튼을 누르면 어떤 요청이 나가죠?"

> 꼬리 질문: "요구사항 2번은 이름과 요청 ID를 '원래 상품 목록 순서'로 둔다고 정했어요. 이걸 '선택한 순서'로 바꾸라는 요구가 오면 `starter.tsx`에서 같이 고쳐야 하는 줄은 어디예요? 그중 한 줄을 빠뜨리면 사용자가 보는 이름 순서와 서버가 받는 `productIds` 순서가 어떻게 어긋나요?"

## 2. 선택을 비웠는데 남아 있는 실패 안내

**상황**: 책상을 선택하고 예약했다. 모의 API는 첫 요청만 실패하므로 0.8초 뒤 빨간 안내 "예약하지 못했어요. 선택한 상품은 그대로예요. 다시 시도해 주세요."가 뜬다. 이때 동료가 상품 목록 위에 아래 `전체 해제` 버튼을 추가했다. `starter.tsx`에는 없는 코드다.

```tsx
<button type="button" onClick={() => setSelectedIds([])}>
  전체 해제
</button>
```

> "실패 안내가 떠 있는 상태에서 `전체 해제`를 누르면 요약과 결과 안내는 각각 어떻게 보여요? 필터를 바꾸거나 상품을 누를 때(51·52번째 줄, 83·84번째 줄)와 비교하면 이 버튼은 무엇을 빠뜨렸죠?"

## 3. form으로 감싼 범위

**상황**: 출제 때 `starter.tsx`에서는 예약 버튼이 `onClick={() => void submit()}`으로 요청을 보냈다. 지금은 상품 목록·요약·결과 안내·예약 버튼을 `<form onSubmit>`(66번째 줄) 안에 넣고 버튼을 `type="submit"`으로 바꿨다. 보기 필터(44번째 줄)는 form 밖에 남겼다. 필터도 요청 중에는 잠기고, 바꾸면 결과 안내를 지운다.

> "form으로 감싸기 전과 후에 사용자가 화면에서 할 수 있는 일이나 보는 것 중 달라진 게 있나요? 필터를 form 밖에 둔 기준은 뭐예요?"
