# 2026-10-06 · 저장 중에 새로 쓴 메모

- 유형: 직접 구현형
- 예상 시간: 30~40분

## 사용자 목표

거래 약속을 메모에 저장하는 동안에도 계속 입력하고, 늦게 도착한 저장 응답 때문에 새로 쓴 내용을 잃지 않는다.

## 핵심 설계 질문

> 저장 요청이 확정한 내용과 지금 작성 중인 내용이 다를 때, 응답은 어디까지 갱신해야 할까요? 이 책임을 어디에서 관리해야 저장·실패·되돌리기가 같은 기준을 사용할까요?

10월 2일은 저장 중 입력을 잠갔지만 **오늘은 입력을 열어 둡니다.** 이 차이가 핵심입니다. `starter.tsx`의 `MemoEditor`에서 로직과 구조를 직접 구현하세요. 현재는 초기값과 미연결 안내만 제공합니다. `view.tsx`는 화면 표현, `api.ts`는 입력과 모의 요청, `Problem.spec.tsx`는 행동 계약을 제공합니다. 표현용 props와 같은 이름의 상태를 각각 만들 필요는 없습니다. 정답 로직·훅·파일 수는 제공하거나 강제하지 않습니다.

## 관찰 가능한 요구사항

1. 처음에는 마지막 저장된 메모와 입력이 `initialMemo`입니다. 입력은 편집할 수 있습니다. 입력과 마지막 저장값을 **문자열 그대로 비교**해 변경이 없으면 두 버튼을 비활성화하고 `저장된 내용과 같아요.`를 표시합니다. 다르면 `아직 저장하지 않은 변경이 있어요.`를 표시합니다. 빈 문자열도 정상 메모이며 공백·줄바꿈을 제거하지 않습니다. 저장된 값이 빈 문자열이면 `저장된 메모가 없어요.`로 표시합니다.
2. 저장 버튼을 누르면 **그 순간 입력한 내용**을 `{ memo }`로 한 번 보냅니다. 요청 중 저장·되돌리기는 잠그되 **입력은 계속 가능**해야 합니다. `요청한 내용을 저장 중이에요. 입력은 계속할 수 있어요.`와 버튼 진행 표시를 제공합니다. 버튼의 접근성 이름은 `메모 저장 중`입니다. 요청 중 추가 입력은 진행 중인 요청 내용을 바꾸거나 별도 요청을 만들지 않습니다.
3. 성공하면 **응답의 memo**를 마지막 저장값으로 반영하고 `요청한 메모를 저장했어요.`를 표시합니다. 입력은 응답 도착 당시 작성 중인 내용 그대로 유지합니다. 요청 이후 추가 수정이 없다면 자연스럽게 변경 없음, 추가 수정이 있으면 성공 안내와 미저장 안내가 함께 표시되어야 합니다. 실패하면 마지막 저장값과 현재 입력 모두 보존하고 `저장하지 못했어요. 작성 중인 내용은 그대로예요. 다시 시도해 주세요.`를 표시합니다. 재시도는 현재 입력을 새 요청으로 보냅니다.
4. 되돌리기는 **가장 최근에 성공한 저장값**을 입력에 복원하고 결과 안내를 지웁니다. 요청 중에는 사용할 수 없습니다. 요청이 끝난 뒤의 새 입력 변경도 이전 성공·실패 안내를 지웁니다. 요청 중에는 진행 안내를 계속 표시합니다. 변경 없음 또는 요청 중 저장 버튼 연타로 중복 요청하지 않습니다.

### 꼭 실행해 볼 순서

| 순서                | 마지막 저장값 | 현재 입력 | 기대 결과                  |
| ------------------- | ------------- | --------- | -------------------------- |
| 진입                | A             | A         | 변경 없음                  |
| B 입력 후 저장 요청 | A             | B         | B를 전송, 입력만 계속 가능 |
| 요청 중 C로 수정    | A             | C         | 요청은 여전히 B            |
| B 응답 성공         | B             | C         | 성공 안내 + 미저장 변경    |
| 되돌리기            | B             | B         | 마지막 성공값 복원         |

요청 중 입력을 초기 A로 다시 바꾼 경우도 확인하세요. B 저장에 성공했다면 저장값은 B, 현재 입력은 A이므로 **미저장 변경**입니다. 단순히 “처음 입력과 같다”는 이유로 변경 없음이 아닙니다.

## 입력·모의 API·실행 환경

```ts
type Memo = { memo: string }
type SaveMemo = (request: Memo) => Promise<Memo>
type MemoEditorProps = { initialMemo: string; saveMemo: SaveMemo }
```

초기 메모는 `저녁 7시에 정문에서 만나기`입니다. 요청 주입 경계는 유지합니다. API는 호출 시 메모를 복사하고 1.8초 뒤 첫 요청만 실패, 이후에는 요청한 내용 그대로 반환합니다. 취소·자동 저장·서버 정규화는 없습니다. 실제 서버나 새로고침 후 저장은 없고 문제를 나갔다 돌아오면 초기화됩니다. 초기값 prop은 한 화면의 진입 값이며, 같은 화면에서 prop 변경에 동기화하는 기능은 범위 밖입니다.

제공 UI·API 테스트 6개는 바로 실행합니다. 직접 구현할 행동 테스트 6개는 `describe.skip` 상태입니다. **풀이 시작 시 `.skip`을 제거해 실패부터 확인**하세요. 건너뛴 상태는 풀이 통과가 아닙니다. 테스트를 통과시키려고 제공된 요구사항을 바꾸거나 검증을 약화시키지 않습니다.

## 화면 맥락·상태·공식 컴포넌트 확인

375px에서 제목 → 마지막 저장된 메모 → 입력 → 변경·진행·결과 안내 → 저장·되돌리기 순서입니다. 나에게만 보이는 기록이므로 게시·결제 기능을 추가하지 않습니다. 단일 인라인 편집이며 별도 시트·리스트·선택 메뉴는 필요하지 않습니다. 상태 경계의 답을 숨긴 채 화면 표현만 제공합니다.

- 입력: 설치된 공식 TextField·TextFieldTextarea 스니펫. 라벨·설명·readOnly·자동 높이 조절을 연결합니다. [Textarea 가이드](https://seed-design.io/components/text-input)에 따라 최소 96px, 최대 240px을 공개 x12 토큰으로 구성합니다. native textarea로 대체하지 않습니다.
- 저장·되돌리기: 공식 ActionButton 스니펫 large, 주 액션 neutralSolid·보조 neutralWeak. 저장 중 입력만 열어 두는 것은 이 문제의 명시 요구사항이며, 출제 스킬의 일반적인 “입력 전체 잠금”보다 우선합니다. 두 버튼은 잠깁니다.
- 실패·성공: 공식 Callout 파츠 critical·positive, alert·status. 성공 안내가 전체 입력 저장 완료를 뜻하지 않도록 `요청한 메모`라고 표현합니다.
- 마지막 저장값·타이포·여백: 공식 Box·Text·VStack과 공개 토큰. 저장된 내용은 비교 기준이라 의미 있는 한 그룹입니다. CSS는 줄바꿈만 보완하고 입력 높이는 공식 Textarea sizing용 style prop으로 지정합니다. 기존 section 전용 native CSS를 피하도록 독립된 article로 구성합니다.
- 사용자가 지정한 Daily SEED 기준을 출제 스킬의 Montage 지침보다 우선합니다. 공식 공통 컴포넌트 문서와 React API, 설치본 타입을 확인합니다.

| 상태         | 표현·조작                                                 |
| ------------ | --------------------------------------------------------- |
| 스타터       | 초기값·로직 미연결 안내, 입력 readOnly                    |
| 변경 없음    | 입력 가능, 두 버튼 비활성                                 |
| 편집·빈 입력 | 입력 가능, 두 버튼 활성                                   |
| 저장 중      | 입력 가능, 두 버튼 잠금, 요청 진행 안내                   |
| 실패         | 현재 입력·저장값 보존, 재시도 가능                        |
| 성공         | 응답만 저장값에 반영, 새 입력이 있으면 미저장 안내도 유지 |

UI 검수용 정적 화면은 `?memo-preview=initial`, `editing`, `empty`, `loading`, `error`, `success`, `success-edited`입니다. 예: `/?memo-preview=success-edited#2026-10-06-save-snapshot`. 고정 데이터이며 사용자 이벤트·저장 상태 전이가 아닙니다. 풀이할 때 query를 지웁니다.
