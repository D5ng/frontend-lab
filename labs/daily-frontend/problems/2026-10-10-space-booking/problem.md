# 우리 모임에 맞는 공간 예약하기

- 유형: 직접 구현형 · 공간 예약
- 예상 시간: 40~60분
- 사용자 목표: 모임 인원과 이용 시간을 정하고 조건에 맞는 공간의 견적을 확인해 예약한다.

## 만들 사용자 흐름

**공간 조회 → 날짜·시간·인원·장비 입력 → 가능한 공간 비교·선택 → 견적 확인 → 예약 결과 확인**

pages/SpaceBookingPage.tsx에서 로직을 직접 구현하세요. 현재는 아무 요청도 하지 않는 미연결 스타터이며, 표현용 booking/SpaceBookingView.tsx와 가상 API·테스트를 제공합니다. 어떤 값을 저장하고 계산할지, 어떤 책임을 함께 둘지는 직접 판단합니다.

## 관찰 가능한 요구사항

1. 진입 시 공간 목록을 조회합니다. 기본 조건은 오늘·10시 시작·2시간·3명·장비 없음이며 공간은 자동 선택하지 않습니다. 조회 대기에는 Skeleton, 실패에는 재시도 안내를 표시합니다.
2. 날짜는 오늘/내일, 시작은 09·10·13·16시, 이용 시간은 1·2·3시간입니다. 인원은 1~10의 정수이고 빈 값·소수·음수·문자는 유효하지 않습니다.
3. 후보는 인원 이상 정원을 갖고, 장비가 필요하면 프로젝터를 지원하며, **예약 구간의 모든 한 시간 단위 슬롯**이 해당 날짜의 hours에 있어야 합니다. 시작 슬롯만 있는 것으로 충분하지 않습니다. 종료는 18시까지 허용하며 18시 이후로 넘어갈 수 없습니다.
4. 예: 오늘 10시부터 2시간이면 10시·11시 슬롯이 모두 있어야 합니다. 10시는 열려 있어도 11시가 빠져 있으면 후보에서 제외합니다. 조건에 맞는 공간이 없으면 조건 변경 안내를 보여 주세요.
5. 날짜·시작·기간·인원·장비 중 어떤 조건이든 바뀌면 이전 공간 선택·견적·예약 안내를 비웁니다. 여전히 후보에 남는 공간도 다시 고르게 합니다. 공간을 선택할 때만 해당 공간의 견적을 보여줍니다.
6. 이용료는 시간당 가격 × 이용 시간, 프로젝터는 예약당 3,000원을 한 번만 더합니다. 장비를 추가하지 않으면 0원입니다. 견적에 공간·날짜·시간 구간·인원과 요금 항목·합계를 표시합니다.
7. 현재 조건에 유효한 선택·견적이 있고 조회·예약 중이 아니며 같은 선택의 예약 성공 상태가 아닐 때만 예약할 수 있습니다. 잘못된 조건이나 빈 목록에서는 요청하지 않습니다.
8. 요청에는 day, 숫자 startHour·duration·guests, projector, spaceId, 숫자 totalPrice를 보냅니다. 예약 중 관련 입력·선택·재조회·중복 예약을 막습니다.
9. 예약 실패는 입력·선택·견적을 보존하고 재시도할 수 있게 합니다. 성공하면 요청한 날짜·시간·공간으로 안내하고 같은 선택의 중복 예약을 막습니다. 조건이나 공간을 바꾸면 안내를 지우고 새로운 예약 과정을 시작합니다.

## 제공 API와 데이터

booking/api.ts의 createBookingApi()는 getSpaces(): Promise<Space[]>와 reserve(input): Promise<{ id }>를 제공합니다. booking/data.ts에서 공간 정원·시간당 가격·장비·오늘/내일의 시간표를 확인할 수 있습니다.

조회 0.35초, 예약 0.7초이며 유효한 첫 예약은 실패하고 재시도는 성공합니다. 새 화면에서는 실패 횟수가 초기화됩니다. 가상 서버는 기본 입력 형식과 공간 ID를 검사하지만 후보·견적 판단 전체를 대신하지 않습니다. 모든 시간은 가상 운영 시간이며 실제 날짜·외부 예약·결제를 사용하지 않습니다.

## 화면·제공 환경과 확인 범위

SEED Design의 공식 TextField, RadioGroup, Select, List 선택 스니펫, ActionButton, Callout, Skeleton, VStack·HStack·Text·Badge를 필요한 역할에 사용합니다. native 컨트롤을 직접 꾸미지 않습니다. 선택·입력·요약·주요 행동이 한 목표로 이어지는 인라인 모바일 페이지이며, 상태 안내는 확인할 수 있도록 화면에 남깁니다. 설치된 React 2.5.1·CSS 2.8.3과 공식 v2 스니펫을 유지합니다.

API는 실제 fetch를 사용하고 날짜 폴더 handlers.ts를 MSW에서 자동 등록합니다. 모의 서버·표현용 View·preview는 제공 환경입니다. 실서버·외부 인증·실제 결제·브라우저 저장소 영속화는 범위 밖입니다. 검사·브라우저 확인 범위는 PR 본문에 명시합니다. 다른 브라우저와 스크린리더 음성 출력은 별도 확인 대상입니다.

가독성·예측 가능성·응집도·결합도는 판단 근거이지 파일·훅 개수에 대한 정답이 아닙니다. 설계 결론과 note.md의 답은 직접 작성하세요.
