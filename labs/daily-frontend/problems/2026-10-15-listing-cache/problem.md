# 다시 연 물건 상세와 요청의 경계

- 날짜: 2026-10-15 (Asia/Seoul)
- 유형: **직접 구현형**
- 예상 시간: **30~40분**
- 사용자 목표: 동네 물건을 번갈아 살펴보며 이미 확인한 상세를 다시 기다리지 않고 읽습니다.

## 시작하기

`starter.tsx`에서 조회·선택·재사용·실패 재시도를 직접 구현하세요. `view.tsx`는 표현만, `api.ts`와 `handlers.ts`는 요청 환경만 제공합니다. 시작 화면은 렌더되지만 아직 API를 호출하거나 물건을 바꾸지 않습니다. 완성 코드나 권장 훅·상태 구조는 제공하지 않습니다.

```sh
pnpm install --frozen-lockfile
pnpm dev:daily --host 127.0.0.1
pnpm --filter @frontend-lab/daily-frontend test problems/2026-10-15-listing-cache
```

공통 Daily 앱에서 오늘 문제 선택 또는 `http://localhost:5173/#2026-10-15-listing-cache`로 접속합니다. 사용 중인 포트는 Vite 출력을 확인하세요. 별도 백엔드는 필요 없습니다. PR의 별도 worktree에서 실행합니다.

먼저 사용자의 목적과 예상 흐름을 `note.md`에 적어 주세요. 동네 게시글 문제에서 배운 “현재 화면과 요청 시점”을 이어서 적용하지만, 이번에는 현재 선택이 아닌 응답도 무조건 버리면 안 됩니다.

## 관찰 가능한 요구사항

1. 진입하면 **접이식 원목 의자**를 선택하고 상세를 한 번 요청합니다. 상품 목록은 제공된 고정 입력입니다. 최초 상세는 비어 있습니다.
2. 선택은 즉시 바뀌고 상세 제목도 선택한 물건을 따릅니다. 새 물건의 상세를 아직 조회하지 않았다면 이전 상세를 숨기고 로딩을 표시합니다. 로딩 중에도 다른 물건 선택이 가능합니다.
3. 성공한 상세는 **상품별로 화면을 떠날 때까지 재사용**합니다. 이미 성공한 물건으로 돌아오면 추가 요청이나 로딩 없이 상세를 표시합니다. `null`(거래 종료)도 성공 결과로 기억합니다.
4. 다른 물건을 보는 동안 도착한 응답도 원래 상품의 결과로 보관합니다. 현재 화면의 상세·오류·로딩은 **현재 선택한 물건**에 속해야 합니다. 예전 상품의 완료가 지금 상품의 로딩을 끝내면 안 됩니다.
5. 같은 상품을 이미 요청 중이라면 다른 상품을 거쳐 돌아와도 새 요청을 만들지 않습니다. 서로 다른 상품의 요청은 동시에 진행할 수 있습니다.
6. 실패는 그 상품의 오류로 기억합니다. 실패한 물건을 다시 선택해도 자동 재요청하지 않고 오류와 **다시 불러오기**를 표시합니다. 재시도 때 그 상품의 오류를 지우고 한 번 요청합니다. 요청 중 재시도는 비활성입니다. 성공한 다른 상품의 결과는 유지합니다.
7. 실패 문구는 `상세를 불러오지 못했어요. 다시 시도해 주세요.`입니다. 정상 상세는 가격·동네·설명을 표시합니다. 거래 종료 결과는 `거래가 종료된 물건이에요. 다른 물건을 골라 주세요.`로 안내합니다.

### 작은 상황

의자 요청(1.8초) → 조명 선택(첫 요청은 0.45초 후 실패) → 의자 응답 도착 → 의자로 돌아오기를 화면에 그려 보세요. 조명 오류가 보일 때 의자 결과는 어디에 남아야 하나요? 의자로 돌아올 때 몇 번째 의자 요청이 발생해야 할까요?

화면과 테스트를 실행하며 확인해도 됩니다. 암산하거나 내부 변수 이름부터 정할 필요는 없습니다.

## 핵심 설계 질문

**현재 선택을 바꾸는 일과 상품별 요청·결과를 보관하는 일은 무엇을 공유하고, 어디까지 독립적이어야 할까요?**

상태와 훅 개수를 먼저 정하지 말고, “의자는 완료했지만 조명은 아직 로딩 중”인 상황을 모델이 표현할 수 있는지 확인하세요. 표현용 props 하나마다 상태 하나가 필요한 것은 아니며 `DetailView` 계약도 필요하면 바꿀 수 있습니다. 파일 수·추상화 개수로 평가하지 않습니다.

## 제공 API와 실행 환경

```ts
type LoadDetail = (id: ListingId) => Promise<ListingDetail | null>
// ListingId: 'chair' | 'lamp' | 'mug'
// ListingDetail: { id, price, description, neighborhood }
```

- `createDetailApi()`는 실제 fetch를 호출합니다. MSW가 `GET /api/daily/2026-10-15/listings/:id` 응답을 모킹합니다.
- 의자: 1.8초 후 성공. 조명: 첫 요청은 0.45초 후 503, 이후 0.45초 후 성공. 머그컵: 0.65초 후 `null`로 정상 성공.
- API 세션마다 첫 실패 횟수를 구분합니다. 다른 문제로 이동했다 돌아오면 새 세션이며 캐시도 초기화해야 합니다.
- API 자체는 캐시나 중복 방지, 취소를 제공하지 않습니다. 함수 주입으로 테스트의 응답 순서를 제어할 수 있습니다.
- localStorage, 전역 캐시, TTL, 서버 재검증, 새로고침 버튼, 외부 데이터 패칭 라이브러리 도입은 범위 밖입니다. 성공 결과의 재조회나 동시 같은 상품 요청 충돌까지 확장하지 않습니다.

## 화면 맥락과 SEED 구성

375px 모바일에서 제목 → 물건 선택 → 해당 상세 순으로 읽습니다. 세 가지 후보를 비교하므로 별도 페이지·시트 대신 인라인 단일 선택으로 제한합니다. 실제 상품 상세 페이지를 그대로 재현하려는 과제가 아니라, 좁은 화면에서 상품 전환을 관찰하기 위한 비교용 UI입니다.

UI 출제 스킬의 Montage 지침보다 사용자 지정 SEED 기준을 우선합니다. 조회 중 **현재 조회 상품의 재시도**만 잠그고 다른 상품 탐색은 허용합니다. 요청 대상과 선택 대상이 다를 수 있다는 요구사항에 따른 입력 잠금 예외입니다.

| UI 역할                    | 공식 대응 컴포넌트와 선택 이유                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 단일 선택·필드 이름/설명   | 설치된 공식 `RadioGroup`/`RadioGroupItem` 스니펫. Field 합성이 포함되어 있고 이름·설명·HiddenInput 연결 제공 |
| 진행/재시도                | 공식 `ActionButton` 스니펫, large/neutralSolid, loading/disabled. 재시도가 필요한 때만 액션 표시             |
| 오류/거래 종료/미구현 안내 | 공식 `Callout` 파츠. critical/neutral, alert/status                                                          |
| 가격·설명·배치             | `Text`, `VStack`, 공개 타이포·색·간격 props                                                                  |

선택은 세로 배치하고 의자를 기본 선택합니다. 라디오 label은 최소 48px 터치 높이를 공개 x12 토큰으로 확보합니다. native 컨트롤로 공식 역할을 대체한 예외는 없습니다. 공통 Daily 선택 메뉴는 기존 SEED Select를 유지합니다.

공식 참고: [Radio](https://seed-design.io/components/radio), [React Radio Group](https://seed-design.io/react/components/radio-group), [Action Button](https://seed-design.io/react/components/action-button), [Callout](https://seed-design.io/react/components/callout).

| 상태            | 표현과 다음 행동                                             |
| --------------- | ------------------------------------------------------------ |
| 시작 코드       | 미구현 안내. 구현 후 최초 조회가 시작되어야 함               |
| 로딩            | 현재 상품 제목·진행 안내, 재시도 비활성, 다른 상품 선택 가능 |
| 오류            | 해당 상품 오류와 명시적 재시도                               |
| 성공            | 가격·동네·설명, 재진입 시 추가 대기 없이 재사용              |
| 거래 종료(null) | 다른 물건을 선택하도록 안내, 종료 결과도 재사용              |

### 표현 검수용 미리보기

개발 서버에서 `?listing-cache-preview=loading#2026-10-15-listing-cache`처럼 query를 hash **앞에** 붙일 수 있습니다. 값은 `loading`, `error`, `success`, `unavailable`입니다. `preview.ts`의 고정 props를 표시할 뿐 클릭·조회·캐시 전이가 구현된 것은 아닙니다. query를 제거하면 실제 풀이 화면으로 돌아옵니다. 프로덕션 빌드에서는 미리보기를 사용하지 않습니다.
