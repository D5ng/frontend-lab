# 현재 날짜에 유효한 픽업 시간

- 유형: 직접 구현형
- 예상 시간: 35~40분
- 사용자 목표: 성수점의 현재 날짜에 예약 가능한 시간만 골라 픽업을 예약한다.

## 핵심 설계 질문

**날짜·목록·선택이 서로 다른 시점에 바뀔 때, “현재 날짜에 유효한 시간만 예약한다”는 약속을 어디에서 관리할까요?**

`starter.tsx`의 `PickupPlanner`에서 로직과 구조를 직접 구현하세요. 화면의 props는 표현 계약이지 상태 설계의 정답이 아닙니다. 지금은 로직 미연결 상태이며 어떤 요청도 실행하지 않습니다. 완성된 로직이나 권장 훅 수는 제공하지 않습니다.

## 관찰 가능한 요구사항

1. 진입 날짜는 오늘입니다. 오늘의 시간을 조회하고, 아직 시간을 자동 선택하지 않습니다. 목록이 준비되어도 직접 시간을 고르기 전에는 예약할 수 없습니다.
2. 날짜를 바꾸거나 `시간 다시 불러오기`를 누르면 **이전 목록·시간 선택·예약 결과 안내를 즉시 비웁니다.** 조회 중에는 시간 조회 안내와 Skeleton을 표시하고 예약·다시 불러오기 버튼을 잠급니다. **날짜는 조회 중에도 바꿀 수 있습니다.** 새 날짜의 조회를 시작합니다. 같은 날짜를 다시 누르는 것은 새 조회가 아닙니다.
3. 성공·실패·요청 완료 중 **현재 화면의 조회에 해당하는 응답만 반영**합니다. 이전 요청의 실패가 현재 목록을 지우거나 이전 완료가 현재 로딩을 끝내면 안 됩니다. 오늘 → 내일 → 오늘처럼 날짜가 되돌아와도 오래된 오늘 응답을 새 요청의 응답으로 취급하지 않습니다. API는 취소를 지원하지 않습니다.
4. 조회 실패 시 목록과 선택은 비어 있고 `시간을 불러오지 못했어요. 다시 불러와 주세요.`를 표시합니다. 재조회는 현재 날짜로 요청합니다. 빈 배열은 실패가 아니며 `예약 가능한 시간이 없어요. 다른 날짜를 골라 주세요.`를 표시합니다. 목록 안에 있는 시간만 선택·예약할 수 있습니다.
5. 예약 버튼은 **현재 조회가 성공한 목록 안의 선택**이 있고, 조회·예약 중이 아니며, 해당 선택의 예약 성공 안내가 없을 때만 활성입니다. 누른 순간 `{ day, slotId }`를 한 번 보냅니다. 예약 중에는 날짜·시간·재조회·예약을 모두 잠그고 버튼 이름은 `픽업 예약 중`입니다. `예약 중에는 날짜와 시간을 바꿀 수 없어요.`를 표시합니다.
6. 예약 실패는 날짜·목록·선택을 보존하고 `예약하지 못했어요. 선택한 시간으로 다시 시도해 주세요.`를 표시합니다. 재시도 시 이전 안내를 지웁니다. 성공은 `오늘 오후 6시 픽업을 예약했어요.`처럼 **요청한 날짜와 시간**으로 안내하고 선택을 유지합니다. 같은 선택의 연속 예약을 막습니다. 다른 시간을 선택하거나 날짜 변경·재조회하면 결과 안내를 지우고 새 선택 과정을 시작합니다. 같은 시간을 다시 누르는 것은 변경이 아닙니다.

### 꼭 확인할 순서

- 오늘의 느린 조회 중 내일로 이동 → 내일 실패 → 재조회 성공 → 옛 오늘 응답: 내일 목록·안내를 유지합니다.
- 오늘 조회 A → 내일 조회 B → 오늘 조회 C → A 도착(C 대기 중): C의 로딩을 유지합니다. C 응답만 반영합니다.
- 오늘 오후 6시 선택 → 내일로 변경: 즉시 선택을 지우며, 내일 목록이 와도 자동으로 시간을 선택하지 않습니다.

## 입력·API·실행

`api.ts`의 `Day`, `Slot`, `LoadSlots`, `ReserveSlot`을 사용합니다. 조회 반환은 `Slot[]`이며, 예약은 성공 시 반환값이 없습니다. 이 주입 경계를 유지하고 테스트에서 원하는 완료 순서를 제어할 수 있게 합니다.

- 오늘 조회: 1.8초, 오후 6시·7시.
- 내일 조회: 0.5초, 첫 내일 조회만 실패, 이후 오전 10시·11시.
- 예약: 1초, 첫 예약만 실패, 이후 올바른 날짜·시간 요청은 성공.
- 빈 배열은 행동 테스트에서 주입합니다. 모의 API는 새 화면 진입 시 초기화하며 실제 서버·새로고침 후 영속 저장은 없습니다.

```sh
pnpm install --frozen-lockfile
pnpm dev:daily
pnpm --filter @frontend-lab/daily-frontend exec vitest run problems/2026-10-08-pickup-slots/Problem.spec.tsx
pnpm --filter @frontend-lab/daily-frontend build
```

Daily에서 오늘 문제를 선택하거나 `#2026-10-08-pickup-slots`로 진입합니다. 제공 UI·API 테스트는 실행되며 직접 구현할 행동 테스트는 `describe.skip`입니다. **풀이 시작 시 `.skip`을 제거하고 실패부터 확인하세요.** 건너뜀은 구현 통과가 아닙니다. 테스트를 통과시키려고 정답을 미리 넣지 않았습니다.

## 화면 맥락·상태

날짜 선택 → 시간 목록 → 예약이라는 한 화면입니다. 선택지가 두 개라 별도 시트 대신 인라인 공식 RadioGroup/RadioGroupItem을 사용합니다. 라벨·설명을 제공하는 Field 통합 스니펫을 사용하며, 날짜는 오늘이 기본값입니다. **시간은 사용자 일정이라 의도하지 않은 예약을 막기 위해 기본 선택을 하지 않습니다.** 공식 권장 기본값에 대한 요구사항상 예외입니다.

조회 중 날짜 조작 허용은 오래된 응답 처리를 연습하는 명시 요구사항입니다. 출제 스킬의 일반적인 전체 입력 잠금보다 이 요구사항을 우선합니다. 예약 중에는 모두 잠급니다. native 컨트롤로 대체하지 않습니다.

- Loading: 공식 Skeleton·Text. 시간 목록 자리를 유지하고 기다리는 대상을 안내합니다.
- Error: 공식 Callout critical·alert. 재조회 또는 예약 재시도로 복구합니다.
- Empty: 공식 Text로 다른 날짜 선택을 안내합니다. 목록/선택 폼이어서 List·Select·Bottom Sheet는 불필요합니다.
- Disabled: 공식 RadioGroup·ActionButton. 왜 예약할 수 없는지 인라인 설명을 제공합니다.
- Success: 공식 Callout positive·status. 예약한 날짜·시간은 확인 정보라 사라지는 토스트 대신 유지합니다.
- 배치: 공식 VStack·HStack·Text와 공개 x2/x3/x4/x6/x12 토큰. 라디오 행의 터치 영역을 위한 HStack 패딩만 보완합니다. CSS·공통 컴포넌트·의존성을 바꾸지 않습니다. Montage보다 지정된 SEED 기준을 우선합니다.

검수용 고정 화면: `?pickup-preview=ready`, `selected`, `loading`, `empty`, `error`, `reserving`, `failed`, `success`. 예: `/?pickup-preview=loading#2026-10-08-pickup-slots`. **정적 화면 데이터이며 상태 전이 구현이 아닙니다. 풀이할 때 query를 지우세요.**

## 완료 조건

1. 행동 테스트를 활성화해 통과하고, 늦은 성공·실패·완료가 현재 날짜·조회·선택에 영향을 주지 않는지 실제 화면에서도 확인합니다.
2. 선택의 유효성을 어디에서 판단했고 어떤 값이 원본인지 `note.md`에 직접 기록합니다. 파일·훅 개수로 정답을 정하지 않습니다.
3. 실제 실행한 검사와 예상한 동작을 구분합니다.

범위 밖: 요청 취소, 캐시, 실시간 마감, 실제 달력, 전역 상태 도구, 서버 영속 저장, 예약 취소. [Frontend Fundamentals](https://frontend-fundamentals.com/code-quality/code/)의 네 기준은 설계 판단의 참고 기준입니다.

## 출제 시 검증 범위

- 최신 origin/develop 기준 별도 worktree에서 frozen lockfile 설치와 정상 훅을 실행했습니다. 오늘 폴더·등록·목록 외에는 변경하지 않았고 원본 체크아웃과 다른 열린 PR은 수정하지 않았습니다.
- 루트 lint·format·test·build(타입 검사 포함) 통과. 오늘 UI·API 테스트 9개 통과, 직접 구현할 행동 6개는 의도적으로 skip입니다. Daily 전체 34개 통과·10개 skip(오늘 6개와 기존 10월 2일 4개), code-quality 22개 통과입니다. 건너뛴 행동을 구현 완료로 계산하지 않습니다.
- 실제 Chromium 375×812에서 스타터 및 고정 상태 화면 8개를 렌더링했습니다. 가로 넘침 없음, 날짜·시간의 입력 라벨과 포커스, 54px 라디오 터치 영역·52px 버튼, 조회 중 날짜 활성·예약 중 전체 비활성, 오류·성공 안내를 확인했습니다. 콘솔 오류·경고가 없었습니다. 고정 데이터만 제공하므로 **조회 순서·날짜 변경에 따른 무효화·실제 예약 전이는 미구현·미검증**입니다. 다른 브라우저와 스크린리더 음성 출력은 미검증입니다.
- `seed-design compat`는 기존 ui:list의 최신 레지스트리 요구 CSS ^3.0.0과 설치본 2.8.3의 차이로 실패했습니다. 오늘은 List를 사용하지 않으며 공식 RadioGroup·ActionButton 스니펫에는 호환 경고가 없습니다. 설치본 React 2.5.1·CSS 2.8.3 타입과 실제 렌더를 확인했습니다. 의존성·lockfile·기존 스니펫을 업그레이드하지 않았습니다. 미완성 행동과 호환 진단 실패를 명시한 Draft PR로 제공합니다.
