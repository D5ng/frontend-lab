# 함께 쓴 돈, 공평하게 나누기

- 유형: 직접 구현형 · 금융
- 예상 시간: 40~60분
- 사용자 목표: 공동 지출의 참여자와 분배 기준을 정하고, 원 단위 합계가 맞는 정산안을 만든다.

## 만들 사용자 흐름

**참여자 조회 → 지출 입력 → 참여자·분배 방법 선택 → 부담 금액 확인 → 정산안 저장**

이번 과제는 pages/ExpenseSplitPage.tsx에서 시작합니다. 조회·검증·분배 계산·결과 무효화·저장 로직은 비워 두었습니다. 제공 View의 props는 표현 계약이며 모두 상태로 보관하라는 뜻이 아닙니다. API 주입 경계는 유지하되 컴포넌트·훅·순수 함수의 구성은 직접 판단하세요.

## 관찰 가능한 요구사항

1. 진입 시 참여자 목록을 조회합니다. 대기에는 Skeleton, 실패에는 재시도 안내를 표시합니다. 빈 목록은 실패와 구분하고, 참여자가 없으면 계산·저장이 불가능합니다.
2. 지출 이름은 앞뒤 공백을 지운 1~~30자입니다. 금액은 1~~1,000,000원의 정수 문자열만 허용합니다. 빈 값, 음수, 소수, 숫자가 아닌 값은 계산하지 않고 입력 수정 안내를 표시합니다.
3. 참여자는 하나 이상 선택해야 합니다. 똑같이 나누기와 참여 횟수대로 나누기를 지원합니다. 횟수는 선택한 참여자별 1~5의 정수이고 기본값은 1입니다. 방식을 왕복해도 횟수 입력은 보존하되 같은 금액 분배에서는 횟수를 사용하지 않습니다.
4. 각자의 몫은 전체 금액에 자신의 비중을 곱한 값입니다. 원 미만은 먼저 버리고, 남은 원은 버린 소수 부분이 큰 사람부터 1원씩 배분합니다. 소수 부분이 같으면 **서버 참여자 목록 순서**가 우선합니다. 선택한 클릭 순서와 무관하게 결과도 서버 순서로 표시합니다.
5. 예: 10,000원을 세 명이 똑같이 나누면 나라 3,334원, 준·봄 각 3,333원입니다. 횟수가 2:1:1이면 5,000원·2,500원·2,500원입니다. 분배 합계는 언제나 입력 금액과 같아야 합니다.
6. 계산하기를 눌러 현재 입력의 결과를 확정합니다. 이름·금액·참여자·방법·횟수 중 하나라도 바꾸면 이전 결과와 저장 안내를 비우고, 다시 계산하기 전에는 저장할 수 없습니다. 유효하지 않은 입력으로 이전 결과를 저장하면 안 됩니다.
7. 저장 요청은 공백을 지운 이름, 숫자 금액, 방법, 선택한 사람의 ID와 숫자 부담액만 보냅니다. 표시용 이름·원 문자열·숨긴 횟수·선택하지 않은 사람은 보내지 않습니다.
8. 저장 중 관련 입력·계산·중복 저장을 막습니다. 실패하면 입력과 계산 결과를 유지하고 같은 정산안으로 재시도할 수 있습니다. 성공하면 정산안 저장 완료를 표시하고 결과를 유지합니다. 실제 송금은 하지 않습니다.

## 제공 API

split/api.ts의 createSplitApi()는 다음 계약을 제공합니다.

- getMembers(): Promise<Member[]> — 0.35초 뒤 가상 참여자 목록을 반환합니다.
- save({ title, totalAmount, method, shares }): Promise<{ id }> — shares는 { memberId, amount } 배열입니다. 유효한 첫 저장은 0.7초 뒤 실패하고 재시도는 성공합니다.
- 잘못된 참여자 ID, 중복 ID, 음수 몫, 합계 불일치는 HTTP 400입니다. 브라우저 화면을 나갔다 돌아오면 실패 횟수는 초기화됩니다.
- 계산 규칙은 이 문서의 가상 규칙입니다. 실제 금융 상품·정책에 대한 문제는 아닙니다.

## 화면·제공 환경과 확인 범위

SEED Design의 공식 TextField, RadioGroup, Select, List 선택 스니펫, ActionButton, Callout, Skeleton, VStack·HStack·Text·Badge를 필요한 역할에 사용합니다. native 컨트롤을 직접 꾸미지 않습니다. 선택·입력·요약·주요 행동이 한 목표로 이어지는 인라인 모바일 페이지이며, 상태 안내는 확인할 수 있도록 화면에 남깁니다. 설치된 React 2.5.1·CSS 2.8.3과 공식 v2 스니펫을 유지합니다.

API는 실제 fetch를 사용하고 날짜 폴더 handlers.ts를 MSW에서 자동 등록합니다. 모의 서버·표현용 View·preview는 제공 환경입니다. 실서버·외부 인증·실제 결제·브라우저 저장소 영속화는 범위 밖입니다. 검사·브라우저 확인 범위는 PR 본문에 명시합니다. 다른 브라우저와 스크린리더 음성 출력은 별도 확인 대상입니다.

가독성·예측 가능성·응집도·결합도는 판단 근거이지 파일·훅 개수에 대한 정답이 아닙니다. 설계 결론과 note.md의 답은 직접 작성하세요.
