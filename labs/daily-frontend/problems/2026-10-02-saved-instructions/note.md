# 풀이 기록

## 어떤 값이 저장의 원본이고, 어떤 값이 편집 중인 값인가요?

저장의 원본:

- `publishedText`: 현재 공개된 안내

편집 중인 값:

- `draftText`: 거래 안내 초안

## 저장 대기·실패·성공에서 각 값과 조작은 어떻게 달라져야 하나요?

대기:

- `draftText`: 사용자가 입력한 값
- `publishedText`: 현재 공개된 안내 텍스트
- 되돌리기, 저장하기, 입력 필드가 disabled 처리된다

실패:

- `draftText`: 사용자가 입력한 값
- `publishedText`: 현재 공개된 안내 텍스트
- 되돌리기, 저장하기, 입력 필드가 활성화된다
- 실패 안내 문구가 보인다

성공:

- `draftText`: 서버가 응답한 값으로 변경된다
- `publishedText`: 서버가 응답한 값으로 변경된다
- 되돌리기, 저장하기가 disabled 처리된다. `publishedText`와 `draftText`가 같기 때문이다.
- 성공 안내 문구가 보인다.

## 고민

`InstructionsEditor`를 중간 컴포넌트로 두었는데, 내가 이렇게 둔 이유는 `InstructionsHeading` 컴포넌트가 리렌더링이 되지 않도록 최적화 하기 위함이였다. 여기서 고민이 들었던건 성능적으로 크게 문제가 되지 않는데 조금이나마의 신경을 쓰는게 맞을까? 라는 생각이 들었다. `React.memo`에 대안도 생각해보았지만 컴포넌트를 캐싱하는 비용이 들기 때문에 컴포넌트의 구조로 해결했다.

이 부분을 AI한테 물어보니, 성능적으로 이야기할거라면 얼마나 더 빨라졌는지에 대한 근거가 필요하다고 했다. 차라리 상태가 함께 변경되는 것들을 묶었다는 응집도 측면으로 작성하는게 더 좋다고했다.

응집도를 생각하고있지만 디테일한 부분까지 신경을 못쓰고있지만, 내가 더 깊게 생각과 고민을 해봐야하는 문제인것 같다.

## 배운 것

함수를 외부에서 주입받는 것과 내부에서 직접 `import`하는 것의 차이:

내부에서 직접 `import`하면 훅이 특정 구현에 묶이기 때문에 재사용이 어렵다. 그 함수에 직접 의존하고 있기 때문이다. 하지만 재사용이 된다는 이유만으로 주입을 고르지 말고 트레이드오프를 따져봐야 한다.

사용할 구현이 하나뿐이라면 내부에서 직접 `import`하는 것이 더 편하고 간단하다. 즉 다른 구현으로 바꿔 끼울 일이 없다면 직접 `import`하는 방향을 선택하자. 미래를 생각해 주입하는 방법도 있지만, 이 방법은 위에서 아래로 prop으로 계속 전달해 주어야 한다. 깊어질수록 전달하는 비용이 커진다.

### 받는 코드를 고치지 않고 다른 구현을 사용할 때

`useInstructionsForm` 훅은 인터페이스에 의존하기 때문에 인터페이스에 맞는 구현체라면 모두 사용할 수 있다.

```tsx
useInstructionsForm({ saveInstructions: createSaveMock() }) // 브라우저: 첫 번째만 실패
useInstructionsForm({ saveInstructions: vi.fn() }) // 테스트: 아무것도 안 함
useInstructionsForm({ saveInstructions: 멈춰_둔_함수 }) // 테스트: 저장 중에 정지
useInstructionsForm({ saveInstructions: 진짜_서버_호출 }) // 나중에 실제 서비스
```

### 같은 코드를 다른 대상에 다시 사용할 때

`useInstructionsForm` 내부에서 저장 함수를 직접 `import`하면 아래와 같이 사용할 수 없다. 훅이 이미 특정 API에 의존하기 때문이다. 이런 경우 의존성 주입으로 훅과 구현체가 모두 인터페이스에만 의존하게 하면 아래 예시처럼 사용할 수 있다.

```tsx
useInstructionsForm({ saveInstructions: saveTradeInstructions }) // 거래 안내
useInstructionsForm({ saveInstructions: saveShopNotice }) // 가게 공지
```
