# 과제 샘플 · 동네 미용실 예약

> 수준을 맞추기 위한 샘플입니다. 읽어 보고 "분량이 이 정도면 된다", "규칙이 너무 많다/적다", "이 부분은 미리 알려 줘야 할 것 같다"를 알려 주세요.

- 예상 시간: 2~3시간
- 주는 것: 사용자 목적, 화면 흐름, 기획 메모, 모의 API, **네 화면의 UI 전부**(예시 값과 빈 핸들러로 그려 둔 SEED + Stackflow 화면)
- 주지 않는 것: 동작(상태, 요청, 규칙 계산), 테스트, 폴더 구조

드릴과 가장 다른 점은 **기획 메모를 코드 규칙으로 바꾸는 일까지 직접 한다**는 것입니다. 기획 메모는 실제 기획자가 쓰는 말투라 "상태", "파생 값" 같은 말이 없습니다.

## 사용자의 목적

> 단골 미용실에서 원하는 디자이너에게, 받고 싶은 시술을 고르고, 가능한 시간에 예약한다.

## 화면 흐름

앱 화면 네 개입니다. Stackflow로 화면을 이동합니다.

```text
가게 홈 ──▶ 시술 선택 ──▶ 날짜·시간 선택 ──▶ 예약 확인(바텀시트) ──▶ 예약 완료
 디자이너 고르기      여러 개 선택         7일 중 하루, 30분 단위
```

## 기획 메모

> 기획자가 슬랙에 남긴 메모를 그대로 옮겼다고 생각해 주세요.

- 디자이너마다 할 수 있는 시술이 달라요. 가게 홈에서 디자이너를 고르면 그 사람이 하는 시술만 보여 주세요.
- 시술은 여러 개 고를 수 있어요. 걸리는 시간은 모두 더해요. 커트 30분에 염색 90분이면 2시간이에요.
- 염색, 펌처럼 같은 종류 시술은 하나만 고를 수 있어요. 다른 염색을 누르면 바꿔 주세요.
- 시술 선택 화면 아래에는 총 금액과 총 시간이 계속 보여야 해요.
- 날짜는 오늘부터 7일만 보여 주세요. 디자이너가 쉬는 요일은 고를 수 없어요.
- 시간은 30분 간격으로 보여 주는데, 고른 시술이 마감 전에 끝나고 다른 예약과 안 겹치는 시간만 누를 수 있어요. 오늘이면 지금 이후 시간만요.
- 고를 수 있는 시간이 하나도 없는 날은 "이 날은 예약이 꽉 찼어요"라고 알려 주세요.
- 예약 확인에서 디자이너, 시술, 날짜, 시작과 끝 시간, 총 금액을 한 번 더 보여 주세요. 결제는 가게에서 해요.
- 예약하기를 눌렀는데 그새 다른 사람이 그 시간을 가져가면 시간 선택으로 돌아가서 다시 고르게 해 주세요. 고른 시술은 그대로 두고요.
- 시간까지 고른 뒤 뒤로 가서 시술을 바꾸는 사람이 있을 거예요. 이때 고른 시간을 어떻게 할지는 정해 주세요. **(결정과 이유를 note.md에 적는다)**

## 모의 API

모든 응답은 MSW로 0.4~0.8초 뒤에 옵니다.

```http

```

  "closeTime": "20:00",
  "designers": [

```http

```

```json
[
  { "start": "13:30", "end": "15:00" },
  { "start": "17:00", "end": "18:30" }
]
```

```http
POST /api/salons/salon-1/bookings
{ "designerId": "d1", "serviceIds": ["cut", "color-basic"], "date": "2026-11-07", "start": "15:00" }
```

| 응답  | 뜻                                   |
| ----- | ------------------------------------ |
| `201` | `{ "id": "b-123" }` 예약 완료        |
| `409` | `{ "code": "SLOT_TAKEN" }` 그새 마감 |
| `500` | 서버 오류. 다시 시도할 수 있다       |

시술 시간이 30분 단위가 아닐 수 있다는 점(두피 클리닉 40분)은 일부러 넣었습니다.

## 해야 할 일

1. **구현 전에** `note.md`에 요구사항 분석을 쓴다.
   - 사용자의 목적과 행동 순서
   - 화면마다 입력과 출력
   - 저장해야 하는 값과 계산하면 되는 값
   - 무슨 일이 있어도 지켜야 하는 규칙 (기획 메모에서 직접 뽑는다)
   - 역할과 책임: 어떤 규칙을 어디에 둘지
2. 그려진 네 화면에 동작을 붙여 끝까지 완성한다. 불러오는 중, 실패, 꽉 찬 날, 409 마감을 포함한다.
3. 행동 테스트를 직접 쓴다. 최소한 아래 세 장면은 테스트로 고정한다.
   - 시술을 바꾸면 고를 수 있는 시간이 바뀐다.
   - 쉬는 요일과 꽉 찬 날을 고를 수 없다.
   - 409가 오면 시술은 남은 채로 시간 선택으로 돌아간다.
4. 직전 드릴 여섯 번 동안 쌓은 `나의 기준.md`에서 실제로 쓴 기준에 표시하고, 쓰지 못한 기준은 왜 그랬는지 한 줄 남긴다.

## 미리 그려 주는 화면

네 화면은 아래 SEED 컴포넌트로 다 그려진 채 주어집니다. 값은 예시로 박혀 있고, 누르는 곳의 핸들러는 `() => {}`로 비어 있습니다. 처음엔 안 보이는 상태는 주석으로 들어 있고, 언제 보여 줄지 한 줄 안내가 붙어 있습니다.

| 화면 / 상태           | 그려 두는 UI                                                       |
| --------------------- | ------------------------------------------------------------------ |
| 화면 틀과 이동        | AppScreen, AppBar (Stackflow). 네 화면이 모두 활동으로 등록돼 있다 |
| 가게 홈               | 디자이너 List, Avatar, 휴무 Badge                                  |
| 시술 선택             | List + Checkbox, 하단 고정 총 금액·총 시간과 ActionButton          |
| 날짜·시간 선택        | 7일 ChipTabs, 30분 단위 ControlChip                                |
| 예약 확인             | BottomSheet                                                        |
| 예약 완료             | 완료 화면                                                          |
| 불러오는 중 (주석)    | Skeleton                                                           |
| 꽉 찬 날, 오류 (주석) | Callout                                                            |
| 그새 마감 (주석)      | Callout                                                            |

다른 화면을 미리 보려면 Stackflow 설정의 `initialActivity`를 잠깐 바꾸면 됩니다. 화면 사이 이동도 동작이라서 연결되어 있지 않습니다.

## 용어집

| 뜻                    | 영어                     |
| --------------------- | ------------------------ |
| 시술                  | `service`                |
| 걸리는 시간           | `duration`, `minutes`    |
| 영업 시작 / 마감      | `openTime` / `closeTime` |
| 휴무 요일             | `dayOff`                 |
| 예약 가능한 시간      | `availableSlot`          |
| 겹치다                | `overlap`                |
| 그새 마감 (선점 충돌) | `conflict`, `slotTaken`  |
| 시술 종류             | `category`               |
