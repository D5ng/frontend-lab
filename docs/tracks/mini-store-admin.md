# Mini Store Admin 학습 트랙

상태 모델링부터 권한과 비동기 동기화까지 하나의 React 관리 도구를 계속 확장하며 설계 변경을 관찰하는 장기 트랙이다. 코드 품질 Lab을 먼저 수행한 뒤 독립 workspace package로 시작한다.

## 목표

- 요구사항을 사용자 행동으로 해석한다.
- 서버, URL, UI, 파생 상태를 구분한다.
- 사용자 목적과 변경 이유로 feature 경계를 설명한다.
- 도메인 정책과 UI 표현을 분리한다.
- 비동기 실패와 캐시 동기화를 설계한다.
- 변경 전후의 영향 범위를 기록하고 필요한 만큼만 리팩터링한다.

## 권장 기술 후보

React, TypeScript, React Router, TanStack Query, React Hook Form, Zod, MSW, Testing Library를 후보로 둔다. 트랙을 시작할 때 실제 요구사항에 필요한 도구만 확정하며, 전역 상태 라이브러리는 필요성이 나타나기 전까지 도입하지 않는다.

## 단계

### 1. 상품 탐색과 상태 모델링

- 상품 목록, 검색, 필터, 정렬, 페이지네이션을 구현한다.
- 검색 조건의 새로고침·공유·뒤로가기 요구를 추가해 URL 상태 여부를 검토한다.
- 입력 값과 실제 검색 값의 분리가 필요한 debounce 요구를 추가한다.
- ProductFilter가 독립 feature인지 상품 탐색 흐름의 일부인지 설명한다.

### 2. 상품 정책과 feature 경계

- 상품 상세, 수정, 삭제, 판매 상태 변경을 구현한다.
- 역할 기반 수정 권한과 상품 상태·판매 이력 기반 삭제 정책을 순차적으로 추가한다.
- 반복되는 조건이 정책적 의미를 얻을 때 명시적인 규칙으로 옮길지 판단한다.
- 수정 UI를 페이지에서 Dialog 또는 inline 방식으로 바꿔 페이지 결합을 확인한다.

### 3. 주문과 서버 상태 동기화

- 주문 목록·상세, 주문 취소, 배송 상태 변경을 구현한다.
- 지연, 실패, 중복 요청과 빠른 연속 검색 응답을 MSW로 재현한다.
- invalidate, 직접 캐시 갱신, optimistic update를 실제 UX와 실패 복구 관점에서 비교한다.
- mutation 성공과 이후 동기화 성공을 별개의 사실로 검토한다.

### 4. 기존 설계 흔들기

- 권한 종류와 세부 권한을 확장한다.
- 단건 작업에 Bulk Action을 추가한다.
- 삭제 정책을 재고, 주문, 판매 기록 조건으로 강화한다.
- 기존 추상화가 변경을 돕는지 방해하는지 분석하고 최종 경계를 정리한다.

## 반복 루틴

```text
요구사항 → 사용자 목적 → 상태·규칙 분류 → 경계 가설 → 첫 구현
→ 변경 요구사항 → 영향 분석 → 필요한 리팩터링 → 학습 기록
```

폴더 구조는 미리 정답으로 고정하지 않는다. `app`, `pages`, `features`, `entities`, `shared`는 트랙의 요구사항이 해당 경계를 필요로 할 때 선택할 수 있는 후보일 뿐이다.
