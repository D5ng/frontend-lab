# 학습 아카이브 로드맵

학습 기록이 충분히 쌓인 뒤 `apps/learning-archive`를 독립 workspace package로 만든다. 지금은 구현 기술과 발행 스키마를 고정하지 않는다.

## 목적

각 카드가 완성 결과만 보여주는 포트폴리오가 아니라 하나의 학습 질문과 판단 과정을 보여주게 한다.

```text
Lab 또는 Project에서 실험
→ notes에 초안 기록
→ 공개할 기록 선별·편집
→ 학습 아카이브의 MDX로 발행
→ 카드 선택 시 상세 학습 기록 표시
```

## 정보 구조

카드 한 개는 폴더 하나가 아니라 하나의 학습 주제를 나타낸다. 장기 프로젝트 하나에서 여러 카드가 나올 수 있다.

상세 화면에는 다음 내용을 포함한다.

- 시작한 질문과 초기 이해
- 관찰 가능한 요구사항과 구현한 내용
- 선택한 설계와 검토한 대안
- 요구사항 변경에서 드러난 영향
- 잘못 이해한 부분과 수정된 관점
- 최종적으로 배운 점
- 관련 코드, 커밋, 데모와 참고 자료

## UI 방향

[Form Follows Function](https://fff.cmiscm.com/#!/main)의 컬렉션형 카드 탐색에서 영감을 얻는다. 시각 표현은 그대로 복제하지 않는다.

- 데스크톱에서는 겹친 카드와 선택 전환을 탐색한다.
- 모바일에서는 가로 목록이나 세로 카드로 단순화한다.
- 카드 선택 상태는 공유와 뒤로가기가 가능하도록 URL로 표현한다.
- 키보드 탐색, 명확한 포커스, 충분한 클릭 영역을 제공한다.
- `prefers-reduced-motion`에서는 큰 회전과 이동을 줄인다.

## 구현을 시작하는 조건

- 공개할 만한 학습 기록이 최소 여러 개 축적되었다.
- 초안 형식에서 반복되는 필드가 확인되었다.
- 카드 분류와 상세 화면에 실제로 필요한 정보가 드러났다.

그 시점에 Vite SPA와 정적 사이트 프레임워크를 배포 환경, 검색 필요성, MDX 처리 비용을 기준으로 비교한다.
