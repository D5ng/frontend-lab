# Exercise 03 요구사항: 생활 할 일

## 목표

사용자는 일상에서 잊기 쉬운 일을 한 화면에서 확인하고, 완료 상태를 관리할 수 있어야 한다.

이 실습은 할 일 목록, 검색어와 필터를 바탕으로 화면에 필요한 값을 만드는 과정을 다룬다. 백엔드 연동이나 할 일 생성 기능보다 **상태의 원본과 파생값을 구분하는 판단**이 핵심이다.

## 사용자와 화면 맥락

- 사용자는 오늘과 가까운 시일에 처리할 생활 할 일을 관리한다.
- 화면은 모바일 앱의 홈이며 너비 375px을 기준으로 한다.
- 사용자는 화면 상단에서 오늘의 진행 상황을 빠르게 파악한다.
- 이어서 할 일을 검색하거나 상태별로 좁혀 보고, 완료 상태를 변경한다.
- 특정 회사의 화면을 복제하지 않는다. 빠른 이해, 쉬운 조작, 생활 밀착형 문장을 제품 품질 기준으로 삼는다.

## 할 일 데이터

각 할 일에는 다음 정보가 있다.

- 다른 항목과 구분되는 식별자
- 제목
- 카테고리
- 예정 시각
- 장소
- 완료 여부

같은 제목을 가진 할 일이 둘 이상 존재할 수 있다. 제목은 항목 식별자가 아니다.

## 오늘의 진행 상황

- 전체 할 일 중 미완료 개수를 `오늘 남은 일 N개`로 보여 준다.
- 완료 개수와 전체 개수를 `완료 개수 / 전체 개수`로 보여 준다.
- 진행률은 완료 개수를 전체 개수로 나눈 백분율이다.
- 할 일이 하나도 없다면 진행률은 0%다.
- 완료 상태나 목록이 바뀌면 모든 진행 정보가 함께 갱신된다.

## 검색과 상태 필터

- 상태 필터는 `전체`, `할 일`, `완료` 세 가지다.
- 처음에는 `전체`가 선택되어 있다.
- 각 필터에는 현재 목록을 기준으로 한 항목 개수를 표시한다.
- `할 일`은 미완료 항목만, `완료`는 완료 항목만 보여 준다.
- 검색은 할 일 제목을 기준으로 하며, 앞뒤 공백과 대소문자 차이로 결과가 달라지지 않는다.
- 검색어와 상태 필터가 모두 있다면 두 조건을 모두 만족하는 항목만 보여 준다.
- 조건에 맞는 항목이 없으면 이유를 이해하고 다음 행동을 선택할 수 있는 빈 상태를 보여 준다.

## 완료 상태 변경

- 각 항목의 완료 버튼으로 완료와 미완료를 전환할 수 있다.
- 완료된 항목은 제목과 완료 버튼의 시각 상태가 달라진다.
- 상태 변경 후 진행 상황, 필터 개수와 현재 목록이 서로 모순되지 않아야 한다.
- 버튼의 접근 가능한 이름만으로 어떤 항목에 어떤 변경이 일어나는지 알 수 있어야 한다.

## 완료한 일 정리

- `완료한 일 정리 N` 버튼은 현재 완료된 모든 항목을 목록에서 제거한다.
- 완료된 항목이 없다면 버튼을 사용할 수 없다.
- 정리 후 제거한 개수를 화면에서 안내한다.
- 제목이 같은 항목이 있어도 완료되지 않은 항목은 제거하지 않는다.

1. 사용자의 행동으로 직접 바뀌는 값은 무엇인가?
2. 다른 값만 알면 매 렌더링마다 다시 구할 수 있는 값은 무엇인가?
3. 계산한 값을 별도 상태로 저장하면 어떤 변경에서 서로 어긋날 수 있는가?
4. 모든 계산을 `Problem`에 두는 것과 이름 있는 함수로 분리하는 것은 각각 어떤 비용이 있는가?
