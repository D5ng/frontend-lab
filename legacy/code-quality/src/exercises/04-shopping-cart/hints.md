# Exercise 04 힌트

필요한 단계까지만 읽습니다. 이 문서는 완성 코드를 제공하지 않습니다. 힌트는 현재 공개된 단계만 다룹니다.

## 1단계

### 높은 레벨: 사용자가 바꾸는 것

1. 사용자가 이 화면에서 직접 바꾸는 값은 몇 개인가요?
2. 총 결제 금액은 사용자가 바꾸는 값인가요, 바뀐 값의 결과인가요?

### 중간 레벨: 지금 나눌 이유가 있는가

1. 수량을 1개 아래로 못 내리게 막는 규칙은 어디에 있어야 사용자가 절대 0개를 볼 수 없나요? 버튼을 막는 것만으로 충분한가요?
2. 이 코드를 누가, 어떤 이유로 바꾸자고 할까요? 그 이유가 지금 요구사항에 적혀 있나요?
3. 분리하고 싶은 코드가 있다면, 그 마음은 지금 읽기 불편해서인가요, 나중이 걱정되어서인가요?

### 낮은 레벨: 현재 코드

- 화면은 수량과 금액을 고정된 값으로 그리고 있다.
- `수량 줄이기`는 항상 비활성 상태다.

1. 고정된 값 중 상태가 되어야 하는 것은 무엇이고, 그 값에서 계산되어야 하는 것은 무엇인가요?
2. `18,900원`이라는 문자열은 화면에 두 번 나옵니다. 둘은 같은 값인가요, 다른 의미의 값인가요?

## 2단계

### 높은 레벨: 무엇이 새로 생겼나

1. 상품이 하나일 때는 필요 없었는데 여러 개가 되면서 새로 필요해진 것은 무엇인가요?
2. 화면이 기억해야 하는 것은 1단계에서 어떻게 달라졌나요? 계산하면 되는 것은요?

### 중간 레벨: 1단계의 판단을 다시 보기

1. 1단계 `note.md`에 적은 "훅으로 뺄 신호"가 이번 변경에서 나타났나요? 나타났다면 어느 순간이었나요?
2. 상품마다 반복되는 화면을 따로 꺼낼 이유가 지금 생겼나요? 꺼낸다면 그 부분은 무엇을 알아야 하고, 무엇은 몰라도 되나요?
3. 처음 풀이(`fbe9a52`)에서 미리 만들었던 것 중 이번에 실제로 필요해진 것과, 여전히 필요 없는 것은 무엇인가요?

### 낮은 레벨: 현재 코드

- 1단계 코드는 수량을 숫자 하나로 기억한다.
- 최소 수량 규칙과 가격 표시는 이름 있는 함수로 되어 있다.

1. 수량을 바꾸는 함수는 이제 "어느 상품의" 수량인지를 어떻게 알 수 있나요?
2. 한 상품의 수량을 바꿀 때 다른 상품이 그대로라는 것은 코드의 어느 부분이 보장하나요?
