# 2026-09-30 · 늦게 도착한 검색 결과

- 유형: 비동기 버그 분석
- 예상 시간: 20분

## 사용자 목표

상품을 찾는 사용자가 검색어를 빠르게 바꿔도, 화면에서 지금 입력한 검색어의 결과와 진행 상태를 확인할 수 있어야 합니다.

## 상황

[`starter.tsx`](./starter.tsx)의 `ProductSearch`는 검색어가 바뀔 때마다 `searchProducts`를 호출합니다. 다음 순서로 요청이 완료됩니다.

1. 사용자가 `맥`을 입력해 첫 요청이 시작됩니다.
2. 곧바로 `맥북`을 입력해 두 번째 요청이 시작됩니다.
3. `맥북` 요청이 먼저 완료됩니다.
4. `맥` 요청이 뒤늦게 완료됩니다.

현재 코드에서는 이전 요청이 최신 결과를 덮어쓸 수 있습니다. 이전 요청의 `finally`도 최신 요청이 아직 진행 중일 때 로딩 표시를 지울 수 있습니다.

## 완료 조건

1. 위 순서에서 화면에는 `맥북`의 결과만 남습니다.
2. 오래된 요청이 완료되어도 최신 요청이 진행 중이면 `검색 중...`이 유지됩니다.
3. 검색어를 지운 뒤에는 결과가 비고, 이전 요청이 뒤늦게 완료되어도 다시 나타나지 않습니다.

## 생각할 질문

> 어느 요청이 현재 검색어에 해당하는지는 어디서 판단할 수 있을까요? `searchProducts`가 요청 취소를 지원하는 경우와 지원하지 않는 경우를 나눠 생각해 보세요.

## 범위

검색 실패 안내, 입력 지연 처리, 화면 디자인 변경은 이번 문제의 범위에 포함하지 않습니다. 먼저 위 세 가지 동작을 만족시키는 가장 작은 변경을 찾아보세요.
