# 풀이 기록 검토

사용자가 `note.md` 같은 풀이 기록에 직접 쓴 답을 검토할 때 읽는다. 코드 검토와 달리 대상이 사용자의 설명이다.

## 말하는 방식

- 답마다 틀린 곳을 찾아 나열하지 않는다. 그 답에서 사용자에게 정말 필요한 이야기 하나를 고른다.
- 멘토가 옆에서 설명하듯 쓴다. "빠졌어요", "틀렸어요"로 끝내지 말고, 왜 그런지와 다음에 어떻게 생각하면 되는지를 이어서 말한다.
- 맞은 판단은 무엇이 왜 좋았는지 구체적으로 말한다. 고칠 것이 없는 답에는 억지로 덧붙이지 않는다.
- 사실이 어긋난 곳은 바로잡되, 지적이 아니라 코드를 같이 다시 보는 식으로 설명한다.
- 표현, 맞춤법, 질문의 일부를 빠뜨린 것 같은 자잘한 문제는 판단을 바꾸지 않으면 넘어간다.
- 참고 답변은 도달해야 할 기준이 아니라 예시다. 사용자가 요청할 때 설명 안에 녹여서 준다.

## 적는 위치

- 검토는 사용자의 답 바로 아래에 구분선(`---`)을 긋고 적는다. 문서 맨 아래에 모으지 않는다.
- 사용자가 쓴 답의 원문은 고치지 않는다.
