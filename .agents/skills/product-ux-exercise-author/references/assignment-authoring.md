# 과제 출제

제품으로서의 화면 설계가 끝난 뒤에 읽는다. 여기서는 그 화면을 **UI는 다 그려져 있고 동작은 하나도 없는** 과제로 바꾼다.

과제의 주제는 화면 그리기가 아니라 그려진 화면 뒤에 상태와 규칙을 어떻게 놓을지다. 그래서 UI는 빠짐없이 주고, 판단할 거리는 하나도 미리 풀어 주지 않는다.

## 산출물

`labs/assignments/problems/YYYY-MM-DD-slug/`

| 파일 | 내용 | 누가 쓰는가 |
| --- | --- | --- |
| `problem.md` | 첫 줄 `# 과제 이름`. 사용자 목적, 화면 흐름, 기획 메모, API 계약, 해야 할 일, 그려 둔 화면 목록, 용어집 | 출제자 |
| `handlers.ts` | 모의 API. 풀이 대상이 아니다 | 출제자 |
| `App.tsx` | `App`을 내보낸다. Stackflow 설정과 화면 등록 | 출제자 |
| `screens/*.tsx` | 화면마다 파일 하나. 다 그려진 정적 UI | 출제자 |
| `note.md` | 요구사항 분석 항목의 빈 제목 | **실습자가 채운다** |

- 등록 파일은 없다. `App.tsx`가 있으면 앱 목록에 자동으로 나온다.
- 실습자는 `screens/`를 그대로 쓰든, 합치든, 옮기든 자유다. `App.tsx`에서 `App`을 내보내는 약속만 지킨다.
- 예시: `docs/tracks/clean-code-drills-assignment-sample.md`

## 정적 UI 규칙

**주는 것**

- 모든 화면을 SEED 컴포넌트로 끝까지 그린다. 목록, 입력, 버튼, 결과, 하단 고정 바까지 출시 화면처럼.
- 값은 예시로 박는다. 목록은 두세 항목을 **반복해서 그대로 쓴다.** `map`으로 바꾸는 것도 실습자 몫이다.
- 예시 값은 `handlers.ts`가 돌려주는 데이터와 같은 이름과 숫자를 쓴다. 실습자가 "이 글자가 응답의 어느 필드인지" 바로 대응시킬 수 있게 한다.
- 누르는 곳의 핸들러는 `() => {}`로 비워 둔다.
- Stackflow 활동은 모든 화면을 등록하고, `initialActivity`는 첫 화면으로 둔다. 화면 사이 이동은 연결하지 않는다.
- 처음엔 안 보이는 상태(불러오는 중, 오류, 빈 결과, 결과 화면, 그새 마감 등)는 **주석 처리한 JSX 블록**으로 넣고, 바로 위에 언제 보여 줄지 한 줄을 쓴다.

```tsx
{/* 이 날 고를 수 있는 시간이 하나도 없을 때 시간 목록 대신 보여 주세요. */}
{/* <Callout tone="neutral" description="이 날은 예약이 꽉 찼어요. 다른 날을 골라 주세요." /> */}
```

- 주석을 풀면 그대로 컴파일되게 쓴다. 필요한 import는 미리 해 두고, 사용하지 않는 import 경고가 나면 그 줄에 이유를 적은 eslint 예외를 둔다.
- 시트를 열고 닫거나 칩이 눌린 모양을 보여 주는 것처럼 **SEED 컴포넌트가 스스로 하는 UI 반응**은 그대로 둬도 된다(`defaultValue`, `BottomSheetTrigger`). 그 값으로 무엇을 계산하거나 요청하는 일만 비운다.

**주지 않는 것**

- `useState`, `useEffect`, 요청, 계산 함수, 커스텀 훅
- 화면 사이 이동
- 공통 컴포넌트로 묶기, 폴더 나누기
- 테스트

## `problem.md`

1. **사용자의 목적** 한 문장
2. **화면 흐름**: 화면 이름과 화살표
3. **기획 메모**: 기획자 말투. "상태", "파생 값" 같은 말을 쓰지 않는다. 결정을 맡길 지점이 있으면 "(결정과 이유를 note.md에 적는다)"로 표시한다
4. **모의 API**: 요청과 응답 예시, 상태 코드별 뜻
5. **해야 할 일**: 요구사항 분석 → 동작 붙이기 → 행동 테스트(최소 장면 세 개를 적는다) → `나의 기준.md` 표시
6. **그려 둔 화면**: 화면·상태별로 어떤 SEED 컴포넌트가 들어 있는지, 주석으로 들어 있는 것은 무엇인지
7. **용어집**

## `handlers.ts`

- 실제 서버처럼 0.4~0.8초 지연을 둔다.
- 오류 상태를 화면에서 직접 볼 수 있게 재현 방법을 하나 둔다. 예: 특정 시간에 예약하면 409. 재현 방법은 `problem.md`에 적는다.
- API 경로는 `/api/assignments/slug/...`로 다른 과제와 겹치지 않게 한다.

## 검증

```bash
pnpm --filter @frontend-lab/assignments lint
pnpm --filter @frontend-lab/assignments format:check
pnpm --filter @frontend-lab/assignments test
pnpm --filter @frontend-lab/assignments build
```

375px 뷰포트에서 화면마다 `initialActivity`를 잠깐 바꿔 띄워 보고 원래대로 돌린다. 주석 블록 하나는 실제로 풀어서 컴파일과 모양을 확인한 뒤 다시 주석으로 돌린다.
