## 클린 코드 처방

### 1. 컴포넌트 props · 쓰지도 않는 props를 받아서 넘기기만 할 때 → 조합으로 건너뛰기

중고 거래 앱의 판매글 상세입니다. 찜 상태는 페이지가 들고, 찜 버튼은 맨 위 헤더에 있습니다.

**상황**

```tsx
function ListingPage({ listing }: { listing: Listing }) {
  const { isLiked, toggleLike } = useLike(listing.id)
  return <ListingLayout listing={listing} isLiked={isLiked} onToggleLike={toggleLike} />
}

// 찜은 쓰지 않는데, 헤더에 넘겨 주려고 받는다
function ListingLayout({ listing, isLiked, onToggleLike }: ListingLayoutProps) {
  return (
    <AppScreen>
      <ListingHeader title={listing.title} isLiked={isLiked} onToggleLike={onToggleLike} />
      <ListingBody listing={listing} />
    </AppScreen>
  )
}
```

**처방: 가운데는 자리만 열고, 채우는 건 위에서**

```tsx
function ListingPage({ listing }: { listing: Listing }) {
  const { isLiked, toggleLike } = useLike(listing.id)
  return (
    <ListingLayout header={<ListingHeader title={listing.title} isLiked={isLiked} onToggleLike={toggleLike} />}>
      <ListingBody listing={listing} />
    </ListingLayout>
  )
}

function ListingLayout({ header, children }: { header: ReactNode; children: ReactNode }) {
  return (
    <AppScreen>
      {header}
      {children}
    </AppScreen>
  )
}
```

**왜**: 상황 코드의 `ListingLayout`은 찜을 쓰지 않는데도 찜 props의 이름과 타입을 알아야 합니다. 헤더에 "찜한 사람 12명"을 붙이려면 페이지, 레이아웃, 헤더 세 파일을 고쳐야 합니다. 조합으로 바꾸면 레이아웃은 "머리 자리와 본문 자리"만 알고, 찜 값은 만드는 곳에서 쓰는 곳으로 바로 갑니다. 11월 2일 슬롯이 변형을 줄이려고 자리를 열었다면, 여기서는 가운데를 건너뛰려고 엽니다.

**안 해도 되는 때**: 한 단계만 내려가거나 가운데 컴포넌트도 그 값을 쓴다면 props로 내려 주는 편이 가장 잘 읽힙니다. 로그인 사용자처럼 여러 화면 깊은 곳에서 두루 읽는 값은 자리를 여는 것만으로는 다 건너뛸 수 없으니 Context를 고려합니다.

### 2. 타입으로 막기 · `{} as T`로 시작해 한 줄씩 채우기 → 객체 리터럴로 한 번에 만들기

여행 앱의 숙소 예약입니다. 폼 값을 서버가 받는 요청 모양으로 바꿉니다.

**상황**

```ts
function toBookingRequest(form: BookingForm) {
  const request = {} as BookingRequest
  request.roomId = form.roomId
  request.checkIn = form.checkIn
  request.checkOut = form.checkOut
  if (form.note) request.note = form.note
  return request
}
```

**처방: 반환 타입을 적고 한 번에 돌려주기**

```ts
function toBookingRequest(form: BookingForm): BookingRequest {
  return {
    roomId: form.roomId,
    checkIn: form.checkIn,
    checkOut: form.checkOut,
    note: form.note || undefined,
  }
}
// BookingRequest에 guestCount가 생기면 바로 여기서
// Property 'guestCount' is missing in type '{ ... }' but required in type 'BookingRequest'.
```

**왜**: 10월 31일 `satisfies`에서 잠깐 봤듯이 `as`는 검사가 아니라 "내 말을 믿어"입니다. 빈 객체에 `as`를 붙이는 순간 TypeScript는 필드가 다 찼다고 믿어서, 서버가 `guestCount`를 필수로 바꿔도 아무 데서도 빨간 줄이 안 납니다. 그대로 배포되면 400 응답으로 처음 알게 됩니다. 객체 리터럴로 한 번에 만들면 빠진 필드를 그 자리에서 알려 주고, `chekIn` 같은 오타도 `Object literal may only specify known properties`로 잡힙니다. 두 오류 문구는 tsc 6.0 `--strict`로 확인했습니다.

**안 해도 되는 때**: 검색 조건처럼 필드가 전부 optional인 객체는 채워 나가도 빠질 필수 필드가 없습니다. 그때도 `{} as SearchQuery`가 아니라 `const query: SearchQuery = {}`처럼 타입을 적고 시작하면 검사는 그대로 남습니다.

### 3. 훅 · 페이지 안에 펼쳐 둔 구독 effect → 무엇을 아는지로 이름 붙인 훅

티켓 앱의 예매 대기열 화면입니다. 탭이 가려져 있는 동안에는 순번을 묻지 않으려고 합니다.

**상황**

```tsx
function QueuePage() {
  const [isVisible, setIsVisible] = useState(!document.hidden)

  useEffect(() => {
    const handleChange = () => setIsVisible(!document.hidden)
    document.addEventListener('visibilitychange', handleChange)
    return () => document.removeEventListener('visibilitychange', handleChange)
  }, [])

  const { position } = useQueuePosition({ enabled: isVisible })
  // ...
}
```

**처방: 커스텀 훅으로 꺼내고 "무엇"으로 이름 붙이기**

```tsx
function usePageVisible() {
  const [isVisible, setIsVisible] = useState(!document.hidden)
  useEffect(() => {
    const handleChange = () => setIsVisible(!document.hidden)
    document.addEventListener('visibilitychange', handleChange)
    return () => document.removeEventListener('visibilitychange', handleChange)
  }, [])
  return isVisible
}

function QueuePage() {
  const isVisible = usePageVisible()
  const { position } = useQueuePosition({ enabled: isVisible })
  // ...
}
```

**왜**: `QueuePage`를 연 사람이 알고 싶은 건 "화면이 보일 때만 순번을 받는다"입니다. 상황 코드는 그 "어떻게"가 페이지 맨 위를 차지해서, 페이지가 하는 일보다 브라우저 이벤트를 먼저 읽게 됩니다. 훅으로 꺼내면 페이지에는 "무엇"만 남고, 구독하는 법이 바뀌어도 고칠 곳은 훅 하나입니다.

**안 해도 되는 때**: `useMount(fn)`처럼 "언제 실행할지"만 감싼 훅은 만들지 않습니다. 이름이 effect가 하는 일을 말해 주지 못하면 읽는 사람은 결국 안을 열어 봐야 합니다. react.dev의 커스텀 훅 문서도 `useMount`, `useEffectOnce` 같은 "생명주기" 훅은 피하고, `useChatRoom`처럼 구체적인 쓰임으로 이름 지으라고 권합니다.

## 생각하는 법

### 기획을 코드로 · "3분 안에"는 언제부터, 누구 시계로 셀까?

**장면**: 택시 호출 기획 메모입니다.

> 호출하고 3분 안에 취소하면 취소 수수료가 없어요.

`createdAt + 3분`과 지금을 비교하는 코드가 바로 떠오르는 문장입니다.

**생각 순서**

1. **"3분은 언제부터 세지?"** 호출 버튼을 누른 때일까요, 기사가 배차된 때일까요? 호출 기준이면 2분 만에 배차된 사람에게 남는 무료 시간은 1분뿐입니다. 배차 전 취소는 늘 무료인지도 같이 묻습니다. 기획자가 정할 일이라 질문으로 적어 둡니다.
2. **"누구 시계로 재지?"** 휴대폰 시계는 사용자가 바꿀 수 있고, 그냥 몇 분씩 틀려 있기도 합니다. 그 시계로 마감을 계산하면 누구는 "무료"를 보고 눌렀는데 수수료가 붙습니다. 마감은 서버 시각으로 정해야 합니다. 화면이 받을 값은 "서버가 정한 마감까지 남은 초"입니다.
3. **"딱 3분일 때 누르면?"** 2분 59초에 눌렀는데 요청이 3분 1초에 도착하면 무료일까요? 누른 시각과 도착한 시각 중 무엇이 기준인지는 서버와 기획이 정할 경계입니다. 화면이 혼자 정하지 않습니다.
4. **"그럼 화면은 무엇을 책임지지?"** 남은 시간 안내와, 문구가 "무료 취소 1:12 남음"에서 "취소 수수료 3,000원"으로 바뀌는 시점입니다. 수수료를 매길지는 서버가 판정하니, 취소 확인 시트에는 서버가 다시 계산한 금액을 보여 줍니다.

**코드로 옮기면**

```ts
type CancelPolicy = { freeCancelRemainingSec: number; cancelFee: number } // 서버가 응답한 순간 기준

// 받은 순간부터 센다. 기기 시계가 틀려 있어도 두 시각의 차이만 쓰니 맞는다
function getFreeCancelDeadline(policy: CancelPolicy, receivedAt: number) {
  return receivedAt + policy.freeCancelRemainingSec * 1000
}

function isFreeCancelNotice(deadline: number, now: number) {
  return now < deadline // 안내용. 수수료를 매길지는 서버가 정한다
}
```

**한 줄 요약**: 시간 제한이 붙은 정책을 보면 "언제부터, 누구 시계로, 딱 그 순간엔?"을 먼저 묻습니다. 시간은 서버가 정하고, 화면은 그 시간을 보여 주기만 합니다.

## 기본기

### TypeScript · `if`로 확인했는데 왜 `map` 콜백 안에서는 또 `undefined`일 수 있다고 할까?

```ts
function applyCoupon(order: Order) {
  if (!order.coupon) return order.items
  return order.items.map((item) => discount(item, order.coupon))
  // Argument of type 'Coupon | undefined' is not assignable to parameter of type 'Coupon'.
}
```

TypeScript는 콜백이 언제 실행될지 모릅니다. 확인한 뒤 콜백이 실제로 돌기 전에 누군가 `order.coupon`을 바꿀 수도 있으니, 속성에 대한 좁히기는 콜백 안으로 가져가지 않습니다. `order`가 `const`여도 그 안의 속성은 바뀔 수 있으니 같습니다. 값을 변수로 꺼내면 풀립니다. `const { coupon } = order`로 꺼내 확인하면 `coupon`은 바뀔 수 없으니 콜백 안에서도 `Coupon`입니다. 매개변수와, 확인한 뒤로 다시 대입하지 않는 `let`도 TypeScript 5.4부터 좁힌 타입이 콜백 안에서 유지됩니다(tsc 6.0 `--strict`로 확인).

**실무에서 만나는 장면**: 위에서 분명히 `if`로 걸렀는데 `filter`, `map`, `setTimeout` 안에서만 빨간 줄이 생길 때. `order.coupon!`으로 덮기 전에 변수로 한 번 꺼내 봅니다.

### React · `Suspense`로 감쌌는데 왜 fallback이 안 보일까? (React 19 기준)

```tsx
function CommentList({ postId }: { postId: string }) {
  const [comments, setComments] = useState<Comment[]>([])
  useEffect(() => {
    fetchComments(postId).then(setComments)
  }, [postId])
  return <List items={comments} />
}

// 게시글 화면
return (
  <Suspense fallback={<CommentSkeleton />}>
    <CommentList postId={postId} />
  </Suspense>
)
```

`Suspense`는 아래 컴포넌트가 무언가를 기다리는지 스스로 알아내지 않습니다. 아래 컴포넌트가 렌더링 도중에 "아직 준비가 안 됐다"고 멈출 때만 fallback을 보여 줍니다. 멈추게 하는 방법은 정해져 있습니다. `lazy`로 불러오는 컴포넌트, 그리고 `use`로 읽는 Promise(서버 컴포넌트가 넘겨줬거나, Suspense를 지원하는 프레임워크·라이브러리가 캐시해 둔 것)가 대표적입니다. effect나 이벤트 핸들러 안에서 보낸 요청은 렌더링 바깥에서 시작되니 `Suspense`는 모릅니다. 위 코드는 빈 목록을 먼저 그렸다가 응답이 오면 채웁니다(react.dev `Suspense` 문서로 확인).

**실무에서 만나는 장면**: TanStack Query의 `useQuery`로 받는 목록을 `Suspense`로 감쌌는데 스켈레톤 대신 빈 목록이 깜빡일 때. `useQuery`는 멈추지 않고 `isPending`으로 알려 주니, 기다림을 `Suspense`에 맡기려면 v5의 `useSuspenseQuery`를 씁니다.

### Next.js · 서버 컴포넌트에서 버튼에 `onClick`을 달았더니 왜 에러가 날까? (Next.js 16 App Router 기준)

```tsx
// app/products/[id]/page.tsx (서버 컴포넌트)
export default async function ProductPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const product = await getProduct(id)
  return <button onClick={() => addToCart(product.id)}>장바구니 담기</button>
}
// Error: Event handlers cannot be passed to Client Component props.
```

서버 컴포넌트가 그린 결과는 브라우저로 보내기 위해 데이터로 바뀝니다(직렬화). 문자열, 숫자, 평범한 객체, 배열, `Date`, `Map`, JSX 같은 값은 보낼 수 있지만, 함수는 코드와 그 함수가 붙잡은 변수까지 함께 가야 해서 보낼 수 없습니다. 예외는 `'use server'`를 붙인 서버 함수입니다. 이때는 함수 자체가 아니라 "서버의 이 함수를 불러 달라"는 참조가 갑니다. 그래서 클릭을 다루는 버튼만 `'use client'` 파일로 떼고, 서버에서는 `productId` 같은 값만 넘깁니다. 10월 30일에 본 `'use client'` 경계를 무엇이 넘을 수 있는지의 이야기입니다(react.dev `'use client'` 문서와 2026년 11월 Next.js 공식 문서로 확인).

**실무에서 만나는 장면**: 서버 컴포넌트에서 `<PriceTag format={formatPrice} />`처럼 함수를 넘겼더니 `Functions cannot be passed directly to Client Components…`가 뜰 때. `onClick`처럼 이름이 `on` 다음에 대문자로 이어지는 prop이면 위 문구, 그 밖의 함수면 이 문구가 뜹니다. 함수 대신 계산한 결과를 넘기거나, 그 함수를 클라이언트 컴포넌트 안에서 import해 씁니다.
