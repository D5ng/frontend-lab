## 클린 코드 처방

### 1. 상태와 파생 값 · 항상 같이 바뀌는 state 두 개 → 하나로 묶기

숙소 예약 앱의 날짜 선택입니다. 달력에서 처음 누른 날이 체크인, 다음에 누른 날이 체크아웃입니다. 범위를 다 고른 뒤 다시 누르면 처음부터 고릅니다.

**상황**

```tsx
const [checkIn, setCheckIn] = useState<Date | null>(null)
const [checkOut, setCheckOut] = useState<Date | null>(null)

function handleSelectDate(date: Date) {
  if (!checkIn || checkOut) {
    setCheckIn(date)
    setCheckOut(null)
  } else {
    setCheckOut(date) // 체크인보다 앞 날짜를 눌러도 그대로 들어간다
  }
}

// 검색창의 "조건 초기화"
const clearDates = () => setCheckIn(null) // checkOut은 남는다
```

**처방: 연관된 state는 하나로**

```tsx
type StayRange = { checkIn: Date | null; checkOut: Date | null }
const EMPTY_RANGE: StayRange = { checkIn: null, checkOut: null }

function selectDate(range: StayRange, date: Date): StayRange {
  if (!range.checkIn || range.checkOut) return { checkIn: date, checkOut: null }
  if (date <= range.checkIn) return { checkIn: date, checkOut: null }
  return { ...range, checkOut: date }
}

const [range, setRange] = useState(EMPTY_RANGE)
const handleSelectDate = (date: Date) => setRange((prev) => selectDate(prev, date))
const clearDates = () => setRange(EMPTY_RANGE)
```

**왜**: "체크아웃은 체크인보다 뒤"라는 규칙이 두 값을 묶고 있습니다. state가 둘이면 setter를 부르는 곳마다 그 규칙을 기억해야 하고, 한쪽만 부르는 곳이 하나라도 생기면 체크인 없는 체크아웃 같은 말이 안 되는 범위가 남습니다. 하나로 묶으면 범위가 바뀌는 길이 `selectDate`와 `EMPTY_RANGE` 둘뿐이고, `selectDate`는 날짜 몇 개만 넣어 보면 테스트됩니다. react.dev의 "State 구조 선택하기"가 첫 원칙으로 꼽는 것도 "연관된 state 그룹화하기"입니다.

**안 해도 되는 때**: 인원 수처럼 날짜와 상관없이 바뀌는 값까지 같은 객체에 넣으면, 인원만 바꿀 때도 `{ ...prev, guests }`를 써야 해서 오히려 번거롭습니다. 묶는 기준은 "늘 같이 바뀌는가"입니다.

### 2. 컴포넌트 props · 자기 바깥 여백을 가진 카드 → 여백은 놓는 쪽이 정하기

복약 알림 앱의 "오늘 먹을 약" 목록입니다. 같은 카드를 홈 화면 위젯에도 하나 놓기로 했습니다.

**상황**

```tsx
function MedicationCard({ medication, isFirst }: { medication: Medication; isFirst?: boolean }) {
  return (
    <div style={{ marginTop: isFirst ? 0 : 12, padding: 16 }}>
      <p>{medication.name}</p>
      <p>
        {medication.time} · {medication.dose}
      </p>
    </div>
  )
}
```

홈 위젯에 하나만 놓을 때도 `isFirst`를 넘겨야 위가 뜨지 않습니다.

```tsx
<MedicationCard medication={nextMedication} isFirst />
```

**처방: 간격은 부모의 gap으로**

```tsx
function MedicationCard({ medication }: { medication: Medication }) {
  return (
    <div style={{ padding: 16 }}>
      <p>{medication.name}</p>
      <p>
        {medication.time} · {medication.dose}
      </p>
    </div>
  )
}
```

카드 사이 간격은 목록이 정합니다.

```tsx
<div style={{ display: 'flex', flexDirection: 'column', gap: 12 }}>
  {medications.map((medication) => (
    <MedicationCard key={medication.id} medication={medication} />
  ))}
</div>
```

**왜**: 카드끼리 12px 떨어지는 건 카드의 모양이 아니라 목록의 사정입니다. 카드가 바깥 여백을 들고 있으면 목록 첫 줄, 홈 위젯, 바텀시트처럼 놓이는 자리마다 여백을 지우는 prop이 하나씩 늘어납니다. 안쪽 여백(`padding`)은 카드의 모양이니 카드가 갖고, 바깥 간격은 놓는 쪽이 `gap`으로 정하면 카드는 어디에 놓여도 같은 모양입니다. SEED의 `VStack`도 자식 사이 간격을 `gap`으로 받습니다.

**안 해도 되는 때**: 한 화면의 한 자리에만 놓이는 블록이면 자기 여백을 가져도 문제가 생기지 않습니다. 두 번째 자리에 놓이게 될 때 빼면 됩니다.

### 3. 비즈니스 로직 위치 · 공용 상품 카드 안의 회원가 계산 → 정책은 밖에서, 카드는 그리기만

쇼핑 앱의 상품 카드입니다. 홈, 검색, 기획전이 같이 씁니다. 골드 등급 이상에게는 10% 할인된 회원가를 보여 줍니다.

**상황**

```tsx
function ProductCard({ product, user }: { product: Product; user: User | null }) {
  const isMember = user?.grade === 'gold' || user?.grade === 'vip'
  const price = isMember ? Math.floor(product.price * 0.9) : product.price

  return (
    <div>
      <p>{product.name}</p>
      {isMember && <s>{formatWon(product.price)}</s>}
      <strong>{formatWon(price)}</strong>
    </div>
  )
}
```

**처방: 가격 정책은 함수로 꺼내고, 카드는 받은 값을 그린다**

```tsx
// 가격 정책: 화면이 없어도 성립하는 규칙
function getDisplayPrice(product: Product, user: User | null) {
  if (!isDiscountMember(user)) return { price: product.price }
  return { price: Math.floor(product.price * 0.9), originalPrice: product.price }
}

// 카드: 원래 가격이 오면 취소선을 긋는다는 것만 안다
type ProductCardProps = { name: string; price: number; originalPrice?: number }

function ProductCard({ name, price, originalPrice }: ProductCardProps) {
  return (
    <div>
      <p>{name}</p>
      {originalPrice !== undefined && <s>{formatWon(originalPrice)}</s>}
      <strong>{formatWon(price)}</strong>
    </div>
  )
}
```

쓰는 쪽에서 정책을 부르고 결과만 카드에 넘깁니다.

```tsx
<ProductCard name={product.name} {...getDisplayPrice(product, user)} />
```

**왜**: "골드 이상 10%"와 카드 모양은 바뀌는 이유가 다릅니다. 등급 기준이 바뀌면 UI 컴포넌트를 열어야 하고, 장바구니나 주문서처럼 같은 회원가가 필요한 곳은 카드 안에 갇힌 계산을 꺼내 쓸 수 없어 한 벌 더 적게 됩니다. 꺼내 두면 정책은 렌더링 없이 테스트되고, 회원가를 보여 주지 않는 화면은 `price`만 넘기면 됩니다. 실제 결제 금액은 서버가 다시 계산하더라도, 목록에서 미리 보여 주는 가격의 기준은 한곳에 있어야 합니다.

**안 해도 되는 때**: 한 화면에서만 쓰는 카드이고 그 가격을 읽는 곳도 거기뿐이면 카드 안에 둬도 됩니다. 두 번째 화면이 같은 회원가를 찾을 때 꺼내도 늦지 않습니다.

## 생각하는 법

### 문제를 풀 때 · 이 값은 새로고침해도 남아야 할까?

**장면**: 채용 앱의 공고 목록을 만듭니다. 지역·직무·경력 필터와 정렬이 있고, 필터는 바텀시트에서 고른 뒤 "적용"을 누릅니다. 일단 전부 `useState`로 두고 시작하려다 손이 멈춥니다. 이 값들이 다 같은 자리에 있어도 될까?

**생각 순서**

1. **"새로고침하면 남아 있어야 하나?"** "서울 · 프론트엔드 · 신입"으로 좁혀 둔 목록이 새로고침 한 번에 풀리면 사용자는 처음부터 다시 고릅니다. 필터와 정렬은 남아야 하고, 바텀시트가 열려 있었는지는 잊어도 됩니다.
2. **"링크를 보내면 받은 사람도 같은 목록을 봐야 하나?"** 친구에게 "이 조건으로 봐 봐" 하고 보낼 수 있어야 한다면 그 조건은 주소(쿼리스트링)에 있어야 합니다. 컴포넌트 state는 그 탭 안에만 있습니다.
3. **"상세에 갔다가 뒤로 오면 어디여야 하나?"** 공고 상세를 보고 돌아왔는데 필터가 풀려 있으면 사용자는 길을 잃습니다. 그런데 필터를 바꿀 때마다 방문 기록이 쌓이면 뒤로 가기가 필터를 하나씩 되돌립니다. 이건 코드로 정하지 않고 기획자에게 물을 질문으로 적어 둡니다. "뒤로 가기를 누르면 이전 필터로 가나요, 이전 화면으로 가나요?"
4. **"'적용'을 누르기 전의 값은?"** 시트 안에서 고르는 중인 값은 아직 사용자의 결정이 아닙니다. 시트를 닫으면 버려도 되니 시트 안의 state로 두고, "적용"을 누를 때 주소로 옮깁니다.

**코드로 옮기면**

```ts
// 주소(쿼리스트링): 새로고침·공유·뒤로 가기에 남아야 하는 값
type JobListQuery = {
  region: string
  role: string
  career: 'all' | 'new' | 'experienced'
  sort: 'recent' | 'deadline'
}

// 화면 state: 닫거나 떠나면 잊어도 되는 값
const [isFilterSheetOpen, setIsFilterSheetOpen] = useState(false)
// 시트가 열릴 때 지금 적용된 조건에서 시작하고, "적용"을 누르면 주소로 옮긴다
const [draftQuery, setDraftQuery] = useState<JobListQuery>(appliedQuery)

// 서버: 찜 여부처럼 원본이 서버에 있는 값은 화면에 한 벌 더 두지 않는다
```

**한 줄 요약**: 값을 어디에 둘지는 코드 구조보다 사용자가 하는 일이 정합니다. 새로고침, 링크 공유, 뒤로 가기를 한 번씩 떠올려 보면 주소에 둘 값과 화면이 잠깐 들고 있을 값이 갈립니다.

## 기본기

### JavaScript · 닉네임 중복 확인을 `async`로 바꿨더니 왜 아무 이름이나 통과할까?

```ts
async function isNicknameAvailable(nickname: string) {
  const res = await fetch(`/api/nicknames/check?value=${encodeURIComponent(nickname)}`)
  const body: { available: boolean } = await res.json()
  return body.available
}

if (isNicknameAvailable(nickname)) {
  goNextStep() // 이미 있는 닉네임이어도 여기로 온다
}
```

`async` 함수는 안에서 무엇을 `return`하든 언제나 Promise를 돌려줍니다. Promise는 객체라서 `if`에 넣으면, 나중에 `false`로 끝날 Promise여도 참으로 읽힙니다. `if (await isNicknameAvailable(nickname))`처럼 결과를 기다린 뒤에 확인해야 합니다.

TypeScript는 `if` 조건에 Promise가 들어가면 `This condition will always return true since this 'Promise<boolean>' is always defined.` 오류와 함께 "Did you forget to use 'await'?"라고 알려 줍니다. 그런데 `candidates.filter(isNicknameAvailable)`나 `const ok = nickname.length > 1 && isNicknameAvailable(nickname)`처럼 `if` 밖에서 쓰면 오류 없이 통과합니다. `filter`는 콜백이 돌려준 Promise를 참으로 보고 전부 남깁니다.

**실무에서 만나는 장면**: 금지어 목록으로 하던 검사를 서버 확인으로 바꾸면서 함수에 `async`만 붙였을 때. 함수를 부르는 곳을 모두 찾아 `await`가 붙었는지 봐야 합니다.

### 네트워크 · 사진을 `FormData`로 올리는데 `Content-Type`을 적었더니 왜 서버가 못 읽을까?

```ts
const form = new FormData()
form.append('title', '자전거 팝니다')
form.append('photo', file)

await fetch('/api/items', {
  method: 'POST',
  headers: { 'Content-Type': 'multipart/form-data' }, // 이 줄이 문제
  body: form,
})
```

multipart 본문은 글자와 파일을 여러 조각으로 이어 붙이고, 조각 사이를 boundary라는 구분 문자열로 나눕니다. 서버는 헤더의 `multipart/form-data; boundary=...`에서 그 문자열을 읽어야 본문을 자를 수 있습니다. `body`에 `FormData`를 넘기면 `fetch`가 boundary까지 넣어 헤더를 만들어 주는데, 직접 `Content-Type`을 적으면 적은 값을 그대로 써서 boundary가 빠집니다. 헤더 줄을 지우면 됩니다.

**실무에서 만나는 장면**: 공통 요청 함수가 모든 요청에 `'Content-Type': 'application/json'`을 기본으로 붙이고 있어서 사진 올리기만 실패할 때. 본문이 `FormData`면 그 헤더를 빼도록 공통 함수에서 갈라 줍니다.

### 브라우저 · 폼 안의 "취소" 버튼을 눌렀는데 왜 저장까지 될까?

```tsx
<form onSubmit={handleSave}>
  <input name="title" defaultValue={todo.title} />
  <button onClick={onCancel}>취소</button>
  <button>저장</button>
</form>
```

`type`을 적지 않은 `<button>`은 폼 안에서 제출 버튼으로 동작합니다. `button.type`을 읽어 보면 `'submit'`이 나옵니다. 그래서 취소를 누르면 `onCancel`이 불린 다음 폼 제출이 이어져 `handleSave`까지 실행됩니다. 제출하려는 버튼이 아니면 `type="button"`을 적습니다.

입력칸에서 엔터를 칠 때도 같은 일이 생깁니다. 엔터로 폼을 제출하면 브라우저는 폼의 첫 번째 제출 버튼에 클릭 이벤트를 보냅니다(HTML 표준의 암시적 제출). 위 코드에서 첫 번째 제출 버튼은 취소라서, 제목을 고치고 엔터를 치면 `onCancel`과 `handleSave`가 둘 다 불립니다.

**실무에서 만나는 장면**: 할 일 수정 화면에서 취소를 눌렀는데 "저장했어요" 토스트가 뜨거나, 엔터를 쳤더니 수정 화면이 닫혀 버릴 때. 공용 `Button` 컴포넌트를 만든다면 `type`의 기본값을 `'button'`으로 두는 방법도 있습니다.
