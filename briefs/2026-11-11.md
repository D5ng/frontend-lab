## 클린 코드 처방

### 1. 비동기와 에러 처리 · 에러 문구를 보고 안내 가르기 → 에러 코드로 가르기

강의 수강 신청 화면입니다. 정원이 찼을 때만 다른 안내를 띄우려고 서버가 보낸 메시지를 들여다봅니다.

**상황**

```tsx
async function handleApply() {
  try {
    await applyCourse(courseId)
    toast('신청했어요')
  } catch (error) {
    const isFull = error instanceof Error && error.message.includes('정원')
    toast(isFull ? '정원이 다 찼어요' : '잠시 후 다시 시도해 주세요')
  }
}
```

**처방: 서버와 약속한 코드로 가른다**

```ts
const APPLY_ERROR_MESSAGE: Partial<Record<string, string>> = {
  COURSE_FULL: '정원이 다 찼어요',
  ALREADY_APPLIED: '이미 신청한 강의예요',
}

// 요청 함수가 응답 본문의 code를 담아 ApiError로 던진다
function getApplyErrorMessage(error: unknown) {
  const code = error instanceof ApiError ? error.code : ''
  return APPLY_ERROR_MESSAGE[code] ?? '잠시 후 다시 시도해 주세요'
}
```

**왜**: 서버 메시지는 사람이 읽으라고 쓴 문구라 언제든 바뀝니다. "정원이 마감되었습니다"가 "자리가 모두 찼어요"로 바뀌는 날, 화면은 아무 오류 없이 "잠시 후 다시 시도해 주세요"를 띄웁니다. `COURSE_FULL` 같은 코드는 문구가 바뀌어도 그대로인 약속이라 분기 기준이 되고, 새로운 실패가 생기면 표에 한 줄만 더하면 됩니다.

**안 해도 되는 때**: 실패를 나눠 안내할 일 없이 "다시 시도해 주세요" 하나면 되는 화면이라면 표를 만들 필요가 없습니다.

### 2. 함수와 인자 · 단위가 안 보이는 숫자 → 이름에 단위 붙이기

공연 예매 앱의 좌석 선점 타이머입니다. 기획은 "좌석을 고르면 5분 동안 잡아 둔다"입니다.

**상황**

```ts
const HOLD_TIME = 300 // 좌석 선점 시간

function startHoldTimer(onExpire: () => void) {
  return setTimeout(onExpire, HOLD_TIME)
}

function formatRemaining(remaining: number) {
  return `${Math.floor(remaining / 60)}분 ${remaining % 60}초`
}
```

**처방: 숫자에 단위를 붙인다**

```ts
const HOLD_SECONDS = 300

function startHoldTimer(onExpire: () => void) {
  return setTimeout(onExpire, HOLD_SECONDS * 1000) // setTimeout은 밀리초를 받는다
}

function formatRemaining(remainingSeconds: number) {
  return `${Math.floor(remainingSeconds / 60)}분 ${remainingSeconds % 60}초`
}
```

**왜**: 상황 코드의 타이머는 5분이 아니라 0.3초 뒤에 만료됩니다. `300`은 초로 정한 값인데 `setTimeout`은 밀리초를 받고, 숫자만 봐서는 아무도 알아채지 못합니다. 이름에 `Seconds`가 붙어 있으면 `setTimeout(onExpire, HOLD_SECONDS)`를 쓰는 순간 "초를 밀리초 자리에 넣고 있네"가 보이고, `formatRemaining(remainingMs)`처럼 부르는 쪽의 어긋남도 눈에 띕니다.

**안 해도 되는 때**: 개수나 횟수처럼 단위가 하나뿐인 숫자, `Date`처럼 값이 단위를 품고 있는 경우는 이름에 덧붙일 게 없습니다.

### 3. 비즈니스 로직 위치 · 화면에서 요청 본문 조립하기 → 요청 함수가 앱 말로 받기

식당 예약 화면의 "예약하기" 버튼입니다. 응답을 받을 때 서버 말(`shop_id`)을 앱 말(`shopId`)로 옮기는 경계를 뒀다면, 보낼 때도 같은 질문을 할 차례입니다.

**상황**

```tsx
async function handleSubmit() {
  await http.post('/reservations', {
    shop_id: shop.id,
    reserved_at: `${form.date}T${form.time}:00+09:00`,
    party_size: form.adults + form.children,
    memo: form.memo.trim() || null,
  })
  navigate('/reservations')
}
```

**처방: 서버 말로 옮기는 일은 요청 함수가 한다**

```ts
// reservation/api.ts
export function createReservation(shopId: string, form: ReservationForm) {
  return http.post('/reservations', {
    shop_id: shopId,
    reserved_at: `${form.date}T${form.time}:00+09:00`,
    party_size: form.adults + form.children,
    memo: form.memo.trim() || null,
  })
}

// 화면은 "예약한다"만 말한다
await createReservation(shop.id, form)
```

**왜**: 화면이 `party_size` 같은 필드 이름이나 "빈 메모는 null로 보낸다" 같은 서버 사정을 알면, 서버가 필드 하나를 바꿀 때 예약을 보내는 화면(새 예약, 다시 예약하기)을 모두 찾아 고쳐야 합니다. 요청 함수가 앱 말로 받으면 서버 사정은 그 파일 하나에 모이고, 화면 코드에는 무엇을 하는지만 남습니다.

**안 해도 되는 때**: 보내는 곳이 한 화면뿐이고 필드 이름까지 서버와 똑같다면 옮길 게 없으니 폼 값을 그대로 넘겨도 됩니다.

## 생각하는 법

### 문제를 풀 때 · 요구사항이 바뀌면 고치기 전에 그 값이 닿는 곳부터 적기

**장면**: 배달 앱 장바구니를 다 만들었는데 기획이 바뀌었습니다.

> 쿠폰은 주문당 한 장이었는데요, 이제 상품 쿠폰 한 장과 배달팁 쿠폰 한 장을 같이 쓸 수 있게 해 주세요.

손은 벌써 쿠폰 시트 파일을 열고 있습니다. 그 전에 몇 가지를 먼저 묻습니다.

**생각 순서**

1. **"지금 '쿠폰 한 장'은 코드 어디에 살고 있지?"** `selectedCoupon`을 검색해서 읽는 곳과 바꾸는 곳을 적습니다. 쿠폰 시트(고른다), 결제 금액 계산(뺀다), 주문 요청(보낸다), 결제 버튼 위 요약 문구(보여 준다). 고칠 곳 목록이 네 줄로 먼저 생깁니다.
2. **"바뀌는 건 값의 모양일까, 계산 규칙일까?"** 할인 방식만 바뀐다면 계산 함수 하나를 고치면 끝입니다. 이번엔 한 장이 두 장이 되니 저장하는 값의 모양이 바뀝니다. 모양이 바뀌면 1번 목록 전부가 영향을 받습니다.
3. **"어디부터 고치지?"** 원본인 state 모양부터 바꿉니다. 그러면 TypeScript가 1번 목록을 한 번 더 확인해 줍니다. 타입 오류가 난 자리를 1번 목록과 맞춰 보면 검색으로 놓친 곳이 드러납니다. 그다음 계산 → 요청 → 문구 순서로 따라갑니다.
4. **"안 바뀌는 건 뭐지?"** 쿠폰 목록을 불러오는 요청, 쿠폰 카드 모양은 그대로입니다. 안 바뀌는 쪽을 적어 두면 "이참에 이것도…" 하며 일이 번지는 걸 막습니다. 두 쿠폰을 어떤 순서로 빼는지처럼 기획에 없는 건 물을 목록에 적습니다.

**코드로 옮기면**

```ts
// 전: 주문당 한 장
const [selectedCoupon, setSelectedCoupon] = useState<Coupon | null>(null)

// 후: 종류마다 한 장. 모양부터 바꾸면 타입 오류가 고칠 곳을 알려 준다
type SelectedCoupons = { product: Coupon | null; delivery: Coupon | null }
const [selectedCoupons, setSelectedCoupons] = useState<SelectedCoupons>({ product: null, delivery: null })
```

**한 줄 요약**: 변경 요청을 받으면 바로 고치지 말고, 그 값을 읽고 바꾸는 곳과 안 바뀌는 곳을 먼저 적습니다. 원본 모양부터 바꾸면 나머지는 타입 오류를 따라가면 됩니다.

## 기본기

### JavaScript · 무료 배달 가게인데 왜 배달팁이 3,000원으로 나올까?

```ts
// 배달팁 정보가 없으면 3,000원으로 보여 준다. 무료 배달 가게는 0을 준다
store.deliveryTip || 3000 // 0이면 3000
store.deliveryTip ?? 3000 // null·undefined일 때만 3000, 0은 0
```

`||`는 왼쪽이 falsy면 오른쪽을 씁니다. falsy에는 `null`, `undefined`뿐 아니라 `0`, `''`, `false`, `NaN`도 들어서, "무료(0원)"와 "정보 없음(null)"을 구분하지 못합니다. `??`는 왼쪽이 `null`이나 `undefined`일 때만 오른쪽을 쓰니 0과 빈 문자열이 값으로 남습니다. 하나 더, `a ?? b || c`처럼 괄호 없이 섞으면 SyntaxError라서 `(a ?? b) || c`처럼 괄호로 묶어야 합니다. Node 24에서 실행해 확인했습니다.

**실무에서 만나는 장면**: 할인율 0%, 재고 0개, 일부러 비워 둔 메모가 기본값으로 바뀌어 보일 때. "없음"과 "0"을 구분해야 하는 자리라면 `??`입니다.

### 네트워크 · 찜 해제는 됐는데 왜 "실패했어요"가 뜰까?

```ts
const res = await fetch(`/api/wishlist/${id}`, { method: 'DELETE' })
if (!res.ok) throw new Error('찜 해제 실패')
return res.json() // 서버가 204로 답하면 여기서 SyntaxError
```

204 No Content는 "성공했고, 돌려줄 본문은 없다"는 뜻입니다. `res.ok`는 `true`인데 본문이 비어 있어서, `res.json()`이 빈 문자열을 JSON으로 읽으려다 SyntaxError로 실패합니다. 요청은 성공했는데 에러가 `catch`로 넘어가니 화면은 실패 안내를 띄웁니다. 본문이 없을 수 있는 응답은 `if (res.status === 204) return`처럼 읽기 전에 확인하거나, 처음부터 본문을 읽지 않습니다. Node 24의 `fetch`(`Response`)로 확인했습니다.

**실무에서 만나는 장면**: 실패 토스트가 떴는데 새로고침하면 찜이 정말 빠져 있을 때. 공통 요청 함수가 응답마다 `res.json()`을 부르고 있지 않은지 봅니다.

### 브라우저 · `type="number"` 입력칸인데 왜 2에 1을 더하면 `'21'`일까?

```ts
// <input type="number">에 2를 입력했을 때
e.target.value // '2', 항상 문자열
e.target.value + 1 // '21'
e.target.valueAsNumber + 1 // 3, 비어 있으면 valueAsNumber는 NaN
```

`input`의 `value`는 `type`과 상관없이 항상 문자열입니다. `type="number"`가 바꾸는 건 숫자 키패드, 위아래 화살표, 유효성 검사 같은 입력 방식이지 값의 타입이 아닙니다. 그래서 `'2' + 1`은 `'21'`이 되고, `'2' * 10000`은 숫자로 바꿔 계산해 20000이 되니 곱하기만 쓰는 동안에는 멀쩡해 보입니다. 숫자가 필요하면 `valueAsNumber`(비어 있으면 `NaN`)나 `Number(value)`(비어 있으면 `0`)로 바꿉니다. 빈칸을 0으로 볼지 "아직 안 씀"으로 볼지에 따라 고릅니다.

state를 `useState(1)`처럼 숫자로 시작했다면 TypeScript가 `setGuests(e.target.value)`에 `Argument of type 'string' is not assignable to parameter of type 'SetStateAction<number>'.`를 띄워 막아 줍니다.

**실무에서 만나는 장면**: 인원 입력칸에 2를 쓰고 + 버튼을 눌렀더니 21명이 될 때.
